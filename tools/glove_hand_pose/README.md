# 12 路 IMU 手套姿态原型

这是第一版实验性工具，用于串口原始数据检查、手动标定、CSV 回放和三维手部姿态显示。它不是经过产品验证的手部追踪系统，也不提供姿态精度保证。现有节点映射实验不能证明关节角、指尖位置或长期漂移精度；合成数据测试通过也不等于真机精度验证。

姿态工具独立位于本目录，不接入 ROS、压力传感器、相机或外部追踪器。仓库根目录的 `Ploy_IMU.py` 可通过 `--config` 使用相同的逐节点单位配置，但仍是独立串口读取者，不能与姿态窗口同时读取一个串口。界面使用 PyQt5 / QPainter 软件渲染实体三维手模型，保留骨架对照视图，不依赖 OpenGL。实体网格在本项目内程序化生成，不需要下载外部人物模型。

默认实体手模型采用雾白材质和淡青色细节，保留原有界面主题及深色预览背景。手形属于示意模型，不是照片级皮肤或个人手型扫描；外观只影响显示，不会更改传感器数据、安装轴或关节角。

当前开发目标：**基于现有 12 路 IMU 硬件推进产品级动捕手套**，不以添加其他传感器为开发前提。2026-09-29 新增自然运动关节标定、角度回放和独立双节点实时实验入口，见下文；开发里程碑见 [IMU 产品化路线与本轮交付](docs/IMU_PRODUCT_ROADMAP.md)。目标不代表已经达到产品级精度。

## 安装与无硬件试运行

在仓库根目录执行，Python 版本要求为 3.10 或以上：

```bash
conda activate visiontactile
python -m pip install -e 'tools/glove_hand_pose[test]'
vt-glove-pose demo
```

`demo` 使用合成关节运动和合成手掌转动，不打开串口。窗口中的“模拟数据”标记是有意保留的：可动模型只证明显示和运动学链路可运行，不代表已连接手套、完成真机标定或达到某种精度。

无桌面环境可运行：

```bash
vt-glove-pose demo --headless --seconds 2
QT_QPA_PLATFORM=offscreen vt-glove-pose demo --smoke-seconds 2
```

第一条不启动图形界面；第二条启动离屏 Qt 界面，约 2 秒后关闭，用于界面冒烟检查。

## 快速全手预览：先看五指和手掌一起运动

希望先跑通完整右手时，使用 `quick-live`。它复用真实串口和逐节点 VQF，**不要求逐指 A/B 标定通过**，不修改旧标定文件；这是快速姿态原型，不是已通过精度验收的产品模式。

在仓库根目录执行：

```bash
conda activate visiontactile
vt-glove-pose quick-live \
  --config tools/glove_hand_pose/configs/right_glove_20260930_empirical.json \
  --port /dev/serial/by-id/usb-STMicroelectronics_STM32_Virtual_ComPort_314E395D3535-if00
```

上面的设备路径属于这只手套；其他设备请用窗口中的串口列表选择。启动仅预填端口，不自动连接。

1. 先断开占用 IMU 串口的旧预览或波形窗口，再点击新窗口的连接按钮；不需要拔插手套。
2. **掌心朝下、五指自然伸直**，点击张手参考按钮。界面先给 3 秒准备时间，再采集 2 秒静止参考；保持到提示完成。此时只建立伸直参考，未对齐的安装方向仍是粗略假设。
3. 点击 **整手坐标对齐**：黄色提示为 3 秒准备，绿色 **“现在开始”** 表示真正采集，持续 10 秒。在绿色阶段保持五指伸直、指形不变，先将整个手掌向下倾斜，让指尖降低约 30°，再回到水平，缓慢重复。**这是转动，不是整手上下平移，也不要握拳或单独弯手指；不要等采集倒计时结束后才开始动作。** 目的是把全部传感器对齐到同一手掌坐标，而不是给每指分别拟合一个弯曲方向。
4. 对齐结束后，再自然握拳、张开、转动手掌观察。拖动模型改变观察视角，滚轮缩放；模型朝向跟随与手指相对动作是两个不同量。

张手参考定义本次显示零位；程序不会把后续任意静止姿势自动拉回伸直。重新佩戴后请重新设置参考。掉线或某指数据过期时显示不可用，不把最后一个姿态当成实时输入。

当前配置把 **12 号当作手掌参考**：它必须固定在手掌／手背并随掌转动，而不能留在桌面或仅随前臂运动。过去拆下小板进行的编号定位测试，不代表之后的安装位置自动正确。若五指在动但 12 号基本不动，应先检查安装位置和动作，而不是连续重复同一标定；参考错误会直接污染五指相对手掌的角度。

早期快速模式的“握拳学习各指轴”已从界面撤下：它可能把整掌运动混入指轴，而且没有保证各指和手掌共用坐标。新版同时统一了拇指的计算中立方向和绘制方向；不再用显示层额外旋转来掩盖二者的不一致。旧原始记录和原 `live` 模式保持不变。

快速模式的安装方向、弯曲与侧摆仍是估计值，不是严格解剖标定。四指末端 DIP 仍由模型推算，六轴航向仍可能漂移，手掌不输出空间平移。当前配置只对 5/6 号使用已提供的经验陀螺比例，其余节点的单位疑点没有被隐藏或自动改写。连续姿态预览也不等于已训练好的手势类别识别器。

## 当前能力与明确限制

下列功能轴要求和拇指配对观察器描述适用于原 `live` / 标定路径；`quick-live` 使用上节说明的临时估计安装轴和全手四元数路径，不会自动安装旧标定或单指候选。

- 每个节点使用 VQF 六轴融合，输入为陀螺仪和加速度计，没有磁力计。六轴航向会漂移，不同节点之间也可能积累相对航向误差；归零与功能轴标定不是无漂移保证。
- 支持整只手随候选手掌参考 Node 12 的旋转改变朝向，前提是本次归零有效、手掌功能轴有效且数据新鲜。朝向相对于本次中立参考，不是无漂移的绝对航向；也可切回手掌局部视图，仅观察手指相对运动。
- 根部平移固定：不估计手在房间中的位置、不积分加速度求全局平移，也不估计真实腕关节相对前臂的姿态。腕部外形只是示意，不能当成前臂测量。
- 四指每指只有两路姿态输入。末端 DIP 屈曲默认按 `0.65 × max(PIP, 0)` 推算，并施加显示范围约束；它不是实测关节角。远端第三骨段在骨架视图用虚线，在实体视图另作推算标记。`estimate_dip=false` 时不输出 DIP 角，末段仍是未观测的直线延伸，不会变成实测骨段。
- 拇指只画两段指骨，不虚构中间指骨；MCP / IP / 侧摆是暂定标签，未建立完整的拇指 CMC、多自由度对掌模型。新版 IP 弯曲采用配对陀螺仪预测 + 条件重力纠偏，不再直接使用两路独立 VQF 航向差；MCP、侧摆与整掌朝向仍走原姿态路径，不能把 IP 改善当成整手绝对无漂移。
- 骨长、指根位置和中立侧摆采用示意值，尚非个体测量。历史求解模板以毫米记录，其名为右手的几何采用拇指 `+x`、指尖 `+y`、手背 `+z`，直接绘制会产生相反的手别外观。显示层现单独校正掌轮廓与指根位置，并依实际配置重定向各指的中立侧摆；保留动态屈曲/侧摆增量和原整掌旋转，不镜像整个测量世界。历史日志、角度、节点映射和标定文件均不改写；原始模型点不能未经上述显示转换就当作已验证的解剖模型。左右手选项不证明另一副左手手套沿用相同节点映射，换手套仍须独立核对映射与安装轴。
- 界面目标刷新率约 30 Hz；这不是 IMU 采样率。每条收到的有效 IMU 样本单独更新滤波器，不把界面刷新周期当作积分周期。

VQF 支持六轴和九轴融合，本工具目前只使用六轴输出。其单位、采样周期及四元数约定见 [VQF 官方文档](https://vqf.readthedocs.io/en/latest/) 与 [FAQ](https://vqf.readthedocs.io/en/latest/faq.html)。本工具将陀螺仪换算为 rad/s、加速度换算为 m/s² 后输入 VQF，四元数统一为 `[w, x, y, z]`。

## 先看到真实运动：免转轴标定的朝向预览

2026-09-30 新增独立入口，把“IMU 已有朝向输出”和“关节轴是否标定成功”分开。**这个窗口不再要求完成六步向导**；适合先检查真实运动是否跟手、各节点映射和单位是否正确。它画两块独立的传感器板及曲线，不把没有完成的解剖标定伪装成手指角度。

### 实时查看

在仓库根目录执行：

```bash
conda activate visiontactile
python -m vt_glove_pose.thumb_preview_live \
  --config tools/glove_hand_pose/configs/right_glove_20260930_empirical.json
```

1. 若其他窗口正在读同一串口，先在那个窗口点击断开；无须关机、重新插拔或删除旧标定。
2. 点“列出串口”，按设备选择 IMU 串口，点“连接”。`--port /dev/ttyACM0` 只能预填，不自动连接；ACM 编号可能随插拔变化。
3. 收到新鲜的拇指两节点数据后，点“以当前姿态为显示参考”，然后自然移动观察。这里不要求屈伸次数、固定近节或拟合转轴；该按钮只建立显示参考，不估计零偏、不认证解剖零位。
4. 断流时板块清空，恢复数据后重新点击显示参考即可。关闭窗口释放串口，不写入设备配置，也不修改旧标定。

注意区分连接与显示参考：若窗口显示“断开”按钮、设置参考按钮可点击，但两块板为空，可能是数据已恢复而旧显示参考已失效。此时点击一次“以当前姿态为显示参考”即可，不必重插、重连或重复标定。该操作仅更改当前显示零位，已保存的测试参考和原始文件不会改变。新版状态提示分别说明串口未连接、等待配对数据、缺少显示参考和正常预览；不会因为没有参考就声称传感器无法连接。

融合逐样本执行，显示约 30 Hz；曲线保留最近约 30 秒的显示快照，不是全速原始数据记录。只查看预览时不录制，下面的引导测试才保存全速原始数据。图中“加速度方向变化”包含线性运动加速度，不能一律当作重力角。

### 一次 31 秒引导测试：不用手抄读数

连接并设置显示参考后，点击 **“开始 31 秒引导测试（自动保存）”**。程序不会自动开始测试，也不会在测试中重设参考或修改滤波偏置。只需看大字提示和倒计时：

| 阶段 | 时长 | 操作 |
| --- | ---: | --- |
| 准备 | 3 秒 | 将小臂、手掌舒适地支撑好，不压传感器板 |
| 开始静止 | 5 秒 | 拇指保持自然参考姿势 |
| 缓慢弯伸 | 12 秒 | 弯曲约 2 秒、返回约 2 秒，共 3 次；近节可自然跟随 |
| 返回 | 3 秒 | 尽量回到开始时的手掌和拇指姿势 |
| 最后静止 | 8 秒 | 保持该姿势，等待保存结果 |

阶段切换有提示音（能否听到取决于系统设置），以屏幕文字和倒计时为准。结束后无需重新标定；界面显示已保存目录。取消、断流或关闭窗口会保留已收数据，并标明测试未完成；不会冒充完成测试。测试期间显示参考按钮禁用。

默认保存到 `~/visiontactile-data/glove_trials/` 下独立的新目录。可在启动时用 `--output-root /path/to/glove_trials` 改目的地。每次测试包含：

- `raw.csv`：实际收到的所有节点原始整数及主机时间；不补造缺失节点，不限于两路拇指。
- `online.jsonl`：每个已配对拇指样本的**实际在线**朝向、角速度、加速度及有效状态，不是界面 30 Hz 抽样或离线重算。若启动时加载了弯曲候选，同一行还包含该次原始配对处理直接产生的 `angle_candidate`（角度、观测来源、预测/丢失状态等）；没有对应输出时明确为 `null`，不会用前一帧或离线角度填补。相同主机时间戳的不同配对仍分别保存。
- `metadata.json`：本次配置、显示参考和计划阶段。阶段标记是操作提示，不证明人真的完成了相应动作。
- `report.json`：每只 IMU 静止阶段的三维朝向变化及首尾参考差异；使用完整四元数比较，不用两个显示幅值相减。
- `manifest.json`：完成／中止状态、文件数量与哈希。发生存储错误时已写文件保留，界面明确提示保存未完成。

这些指标不是关节角精度。首尾差异仍可能包含实际姿势差、安装移动及估计误差；静止提示期间的运动会体现在角速度统计里，数据不足或间断会明确标记。本轮不设置产品验收合格线，也不自动将报告变成标定。录制与在线融合由同一个串口读取者接收数据；最终报告在后台生成，预览继续。

每块板相对于**自己的参考**显示；没有校准两块 IMU 之间的共同航向。因此不能相减两个旋转幅值得到关节角，也不能把两个独立六轴四元数之差当作已校准手指姿态。六轴航向漂移仍需后续关节模型解决。

### 不操作硬件，回放已保存的真实动作

在仓库根目录执行，`/path/to/hinge_export` 指含 `manifest.json`、静止参考和运动 CSV 的完整导出目录：

```bash
python -m vt_glove_pose.thumb_preview /path/to/hinge_export \
  --config tools/glove_hand_pose/configs/right_glove_20260930_empirical.json \
  --output thumb_orientation_preview.json
python -m vt_glove_pose.thumb_preview_gui thumb_orientation_preview.json
```

输出文件必须尚不存在。支持录制段切换、播放/暂停、进度拖动、倍速、独立 3D 朝向和原记录单位／当前配置单位的曲线对比。实线是指定评估配置，虚线是原记录配置；两者用同一批原始整数，**虚线不是角度真值**。

每段运动单独初始化滤波器，以运动首帧为显示参考；独立静止段仅用于估计陀螺零偏。静止段与运动段之间未录下的时间没有被拼接成“连续运动”，因此不能用该回放声称测得了回到原静止姿态的误差。窗口里的再次设置显示参考仅改变板块展示，曲线和文件不变。

### 下一步：连续拇指弯曲量，而不只是两块 IMU 朝向

`thumb_angle_candidate` 将已经保存的 31 秒测试转换为**冻结参数的相对弯曲候选**。它使用项目内的 NumPy 联合转轴求解器，不依赖 qmt；随后由配对陀螺仪预测、重力及横向角速度观测纠偏，直接输出连续角度。实时和离线回放使用同一个逐样本处理模块，不以两路独立 VQF 四元数相减代替关节角。

这条路径允许在严格固定铰链拟合未通过时继续查看**实验曲线**，保留原拟合判定与观测状态，不阻断原有朝向显示；它不会把候选写入全手正式标定。当前是单拇指功能开发入口，不是五指手势分类器，也不是已验证的解剖角。

先从完整导出的测试创建候选。下例时间段针对本轮已检查的数据；换一份记录时，应按实际动作选择静止参考、训练运动和后续验证运动，不能把向导计划时间直接当作真实动作：

```bash
python -m vt_glove_pose.thumb_angle_candidate /path/to/thumb_trial \
  --neutral 3 8 --train 12 21 --holdout 21 30 \
  --output-dir /path/to/new_thumb_candidate
python -m vt_glove_pose.thumb_angle_replay /path/to/new_thumb_candidate/replay.json
```

输出目录必须尚不存在，生成 `candidate.json` 和 `replay.json`，原记录不变。参考段只用于偏置和参考姿态；运动轴只在训练段拟合；后续验证段不参与拟合或选择候选。回放可播放、暂停、拖动和变速，显示关节示意及连续角度。播放到缺失区间时按实际样本年龄清空当前角度，不把上一帧显示成实时观测。启动时即便手指已弯曲，也根据当前观测相对**保存的参考**初始化，绝不强制显示零度；训练结束、验证开始和记录末尾也不会归零。

如果运动包含充分的沿轴重力信息，却被大量近垂直姿态的无信息样本稀释，可以显式比较新方向判定：

```bash
python -m vt_glove_pose.thumb_angle_candidate /path/to/thumb_trial \
  --neutral 3 8 --train 12 21 --holdout 21 30 \
  --frame-sign-strategy informative_blocks \
  --output-dir /path/to/new_thumb_candidate_blocks
```

默认仍为 `whole_capture`，既有候选不会自动迁移。新选项使用原始配对序号的 60 行块，每块至少 30 个有信息点、至少 3 个方向一致的支持块；幅度 `.10`、方向区分 `.10`、残差 `.08` 的实验阈值不变。符号计票只用有信息点，但最终方向必须同时通过所有充分填充的有效块、有效样本全集及有信息子集的残差检查，不能靠长静止或多数正常块掩盖持续冲突。序号块不代表独立设备时间或统计独立样本。它只解决一类符号误拒绝，不会使不一致的转轴变成合格标定；如果仍失败，应保留该结果，不能逐次改阈值直到通过。

实时使用同一个候选：

```bash
python -m vt_glove_pose.thumb_preview_live \
  --config tools/glove_hand_pose/configs/right_glove_20260930_empirical.json \
  --angle-candidate /path/to/new_thumb_candidate/candidate.json
```

仍由一个串口读取者提供数据。手动连接后可直接查看“拇指弯曲（实验）”，不需要重新设置参考或拟合运动轴；“独立朝向”页签使用自己的显示参考，修改它不会重设弯曲角。绿色代表**当前有模型观测支持**，黄色代表短时预测；断流时清空当前值，不把最后一个角度伪装成实时值。信号恢复可重新获得当前角度，但已丢失的轨迹会保留丢失标记。

观察器恢复策略 `bounded_short_gap_anchor_v2`：短暂观测不可用不再一律重新等待 150 ms。已经建立参考观测、软件未检测到陀螺轨迹中断、实际观测缺口不超过 100 ms，且恢复值符合原观测与陀螺积分的一致性约束时，可在恢复样本上继续纠偏。这里的时间来自配置采样周期，不是独立测量的设备时钟；不能排除无序号协议里的静默完整丢帧。真正检测到的缺包/饱和、首次出现的观测源及较长缺口仍保留确认流程。短缺口后的异常跳变不会仅因持续等待超过半秒就变成有效观测；历史缺失标记也不会清除。这是软件恢复行为改进，不是端到端物理延迟或漂移验收。

要验证实际在线表现，先设置一次独立朝向显示参考，再点击已有的“开始 31 秒引导测试”。启用候选时 `metadata.json` 会同时冻结其配置，`online.jsonl` 保存实际在线角度；这不会重新标定，也不会重置观察器。未加载候选的旧记录格式不变。报告中的“计划保持段”只是向导时间窗口，**不是静止已验证**；如果该段仍在运动，其姿态变化不能被误称为静止漂移。原始报告不会因代码更新而被改写。

注意：重新佩戴、传感器松动或安装位置改变后，旧运动轴不一定适用。候选的零位是保存的参考姿态，不自动等于“手指伸直”；正负方向也未完成解剖学确认。曲线一致性、模型创新和软件测试通过均不等于独立角度精度验证。**不需要为了打开新回放而拔插手套，也不要同时启动两个实时串口读取窗口。**

### 一次实验的操作顺序

**2026-09-30 实测注意：**已发现这只右手套的拇指 5/6 号与其他已记录节点存在约 2 倍的角速度换算差异。现在支持逐节点比例，并提供明确标注为实测推断的配置；不能将所有节点统一乘二。下方新配置只修正这项转换，不表示反复失败的固定转轴标定已经解决。先完成离线复核，不要因窗口可启动就重复相同采集。详见下一节。

新版默认显示 **6 步向导、一个主要操作按钮、大字动作提示和分阶段倒计时**。先看屏幕上方的指令，再点大按钮，不需要一次记住所有流程。教学图是右手拇指的操作示意，明确标注“不是传感器测量”；下方双骨段和曲线才显示估计器输出。其他手指仅显示对应文字引导，不冒用拇指教学图。

1. 戴好手套并检查两块 IMU 没有松动；点击“列出串口”，明确选择端口后点击“连接手套”。只有收到新鲜的所选节点配对数据，大按钮才允许开始参考；“串口打开但没有数据”不会被说成手势失败。单位及名义采样率仍须与固件确认，主机接收率不等于设备采样率。
2. 点击“采集静止参考”。屏幕先显示 **准备 3 秒**，可以调整姿势；切换到 **采集中 5 秒**后保持不动。程序使用该段独立参考估计偏置与角度零位，**不会把后续弯曲首帧当作零位**；参考姿势并不自动等于解剖学零度。
3. 看到“静止参考已成功”，不要重复点击参考，点击新的大按钮“开始自然运动”。准备 3 秒，然后约 20 秒缓慢屈伸目标关节，同时轻缓改变整掌朝向，包含不同方向的整体旋转。两块 IMU 都可移动，不需要固定近节。不应只有纯转掌、只沿一个方向转掌或快速甩手。
4. 拟合在后台进行，串口读取继续。候选成功后显示数学角；失败会显示原因并保留原始窗口，不强行生成合格标定。可重做自然运动；断流或重新连接后需重新采集参考。
5. 候选角度有效且可观测时，大按钮变成“确认屈曲方向”。准备 3 秒后，**第一段动作向掌心缓慢弯曲目标关节**，共记录 4 秒。程序用第一段连贯角变化确认正负，不用最后停留点，避免回位造成反号。动作不充分时保留数学角，不自动猜测屈曲方向，也不强行归零。
6. 点击“开始 30 秒试跑”，按大字提示操作：准备参考 3 秒 → 保持参考 2 秒 → 慢屈伸、小幅转掌 15 秒 → 保持自然弯曲 5 秒 → 回到参考 3 秒 → 保持 2 秒。开始与结尾参考时段会作为**向导时间标记**保存；这不是程序检测到了真实参考姿势，动作做错时请保留数据并说明。它不重新拟合、不重设零位，也**不是完整验收**。
7. 试跑结束后，大按钮变成“导出本次实验”；选择父目录。程序新建带时间戳的实验目录，保留失败、取消、成功及验证窗口；不会覆盖旧文件。也可随时在当前动作结束后点击“保存已有数据”，标定失败也能保存。**数据在点击导出前仅存在内存，关闭前应导出。**

如果做错了正在采集的动作，点击“取消本步，保留数据”，再按新的提示开始；不要拔插设备或强行退出。保存中请等待按钮恢复。已经导出静止参考不代表整套标定完成，仍可继续自然运动。

### 失败后不是一律重新采集

向导与采集控制器共用结构化失败原因，提示和下一步按钮保持一致；原始原因、恢复建议及数据一并导出，不靠解析一段提示文字决定流程。

| 当前问题 | 向导下一步 |
| --- | --- |
| 参考姿态的重力方向太接近估计转轴 | 保持指形，先改变整手倾斜，再停稳重采参考；不要保持原朝向反复做 |
| 两路参考加速度幅值不一致 | 保存失败记录，检查单位、固定与数据；不继续使用已不满足条件的参考 |
| 参考与估计轴的重力分量不一致 | 保存参考和运动一起检查；不能只凭该原因断定是参考姿势错了或让你只重采运动 |
| 运动方向信息不足、轴正负不可确定 | 保留参考；屈伸时向不同方向轻缓转掌，再采自然运动 |
| 静止期间波动过大，但两路平均加速度幅值正常 | 先放稳手掌和手指，再重采参考；不是要求更用力或完全伸直到零度 |
| 未识别的配置、计算或数据异常 | 保存记录与错误信息，停止盲目重复；检查后再决定重采哪一步 |

这些是恢复建议，不是对硬件故障或人体操作错误的确诊。所有数据质量阈值不变，不会为了显示成功而放宽门槛。尚未保存的失败记录仍在当前窗口内存中，更新程序前先点击“保存已有数据”。

正式的多次回位/长时保持测试放在“展开高级操作、完整验证与诊断信息”内：可手动选择 **30 / 90 / 180 秒，高级区默认 180 秒**，添加回位、60 秒保持、转掌等动作标记。30 秒向导只有一次返回参考，不满足至少 20 次回位或 60 秒保持的完整候选判据；其报告相应指标显示数据不足，不应解释为程序坏了或精度通过。

当前每个窗口中的原始实验采集有界：标定阶段最多保存 180,000 个所选线路分组原始 `Sample`，独立验证另限 180,000 个。达到限制会停止该次采集而不是无提示循环覆盖；导出后可重新开窗口开始新实验。每个组有 6 个节点；这不是完整 12 路连续录制器。

### 导出与复现

新目录包含 `001_neutral.csv`、`002_motion.csv` 等逐次原始窗口、`candidate_profile.json`（如果当前仍有候选）和 `manifest.json`。实际编号以清单为准，失败或取消的窗口也占编号。每段独立验证另有 `*_validation.csv`、`*_validation_online.json`、`*_validation_preview.json`、`*_validation_profile.json` 和 `*_validation_protocol.json`。

- CSV 保留所选 **6 节点线路分组**的原始整数、状态字和主机解析时间，支持同组内非相邻节点重新配对。它不证明硬件同步。
- 候选文件保留实验/离线标志，不写入旧实时标定。该独立窗口明确选择新观察器作实验预览，不将文件变成产品认证标定。
- `manifest.json` 记录配置、动作结果和文件哈希；`export_complete=true` 才表示导出完成。只有 `export_started.json` 的目录是中断/失败的部分导出，可换一个新目录重试。
- `*_validation_online.json` 保存每个匹配 IMU 对产生的**实际在线角度、偏置、模型不确定度、质量及对应原始整数**。同一个 USB 读取时间下的多对样本分别保留，不按时间戳合并。未初始化/失效时角度为空，不用旧角度或 0 填补。每段最多 30,000 行，丢弃数量明确保存；界面显示当前已记录/丢弃的对数。
- `*_validation_preview.json` 只是显示刷新率的快照，**不是全采样率姿态记录**；全速在线输出在 `online` 文件中。原始 CSV 仍支持独立离线重算，用于比较算法，而不替代当时的在线表现。
- 每段 `*_validation_profile.json` 冻结**录制当时**的候选，后续重做标定不会改变它；`*_validation_protocol.json` 绑定原始 CSV、实际在线输出、当时的候选、文件哈希和操作者动作标记。不要用最后一次 `candidate_profile.json` 替代更早验证的参数。

例如清单中的独立验证文件为 `004_validation.csv` 时：

```bash
vt-glove-pose compare-hinge 004_validation.csv --profile 004_validation_profile.json --max-pairs 30000 \
  --output validation_comparison.json --html validation_comparison.html
```

该比较按候选的数学角方向输出；用户声明的屈曲方向保存在实验清单和对应协议中，不会篡改离线配置。若候选不是 `offline_candidate_ready`，先查看报告，不使用失败候选进行角度回放。`--max-pairs 30000` 可覆盖名义 120 Hz 的 180 秒录制；读取限制不代表数据本身完整。

### 带动作标记的回位／保持验证

建议在成功获得候选后选择 180 秒录制。标记只是**操作者对动作的声明**，不会控制估计器，不会将参考姿势或弯曲姿势设成零；软件也不能仅凭点击证明实际做了对应动作。

1. 保持一个明确、可以重复到达的参考手型，点击“参考手型 · 2 秒”。点击后准备 1 秒，再保持 2 秒。
2. 屈曲目标关节，再回到同一参考手型；到位后点击“已回同一手型 · 2 秒”，准备 1 秒并保持 2 秒。重复至少 20 次真实屈伸，每次单独标记；界面计数是**标记完成次数，不是通过次数**。
3. 保持一个固定的弯曲姿态，点击“固定保持 · 60 秒”，准备 1 秒后持续保持 60 秒。无需将弯曲角视作零，也不要求它是某个已知角度。
4. 保持指形、只轻缓改变整掌朝向，点击“固定指形转掌 · 10 秒”，准备 1 秒后执行 10 秒。它检查当前输出是否发生明显假屈曲，不证明真实指形绝对没变。
5. 如动作做错，点击“取消本次标记”即可，原始数据和取消记录仍保留，录制及角度估计继续。剩余录制时长不足时，不会悄悄缩短 60 秒保持；可开启下一段较长录制。

每个标记的窗口会按原始 CSV 的首个主机解析时间保存；离线程序还会处理第一条原始记录与第一对有效 IMU 样本的时间差，不把按钮时间当设备时间或真实动作开始时间。

导出后，在实验目录运行（编号以实际导出为准）：

```bash
vt-glove-pose validate-hinge 004_validation_protocol.json \
  --output validation_result.json --html validation_result.html
```

默认 `--source auto`：新录制有逐配对在线记录时，直接分析**录制期间真实输出的角度**，不重新初始化观察器。报告核对原始载荷和顺序，保留当时累积的偏置及非零角度；缺失的输出保持为空，不能用离线重算补成“通过”。界面刷新率不会限制这份记录的采样率。

旧协议没有在线文件时，`auto` 兼容离线重算，JSON 的 `provenance.evaluation_source` 和 HTML 页首明确标注 `replay`；如必须分析实际在线表现，指定 `--source online`，缺文件会明确报错。协议已声明在线文件但该文件丢失或校验不符时，不会悄悄回退。旧版本运行期间没有保存的逐配对输出无法事后补回；正在运行的旧窗口需先导出并正常关闭，下次启动新版后再录制。

同一份原始数据可显式重算，使用不同文件名避免覆盖：

```bash
vt-glove-pose validate-hinge 004_validation_protocol.json --source replay --observer constrained \
  --output validation_replay.json --html validation_replay.html
# 旧观察器对照：把 constrained 改成 baseline，并使用另一组输出文件名。
```

`--observer` 只适用于离线重算；不能给保存的实际在线输出更换算法。重算从冻结候选及验证首帧重新初始化，不恢复录制前累积的内部状态，因此与在线结果可能不同。这些命令不修改标定、不打开设备；两类结果均不能代替独立真值或显示端延迟测量。

报告区分三类**候选重复性/稳定性检查**：20 次同姿态回位相对首次参考的偏差 ≤5°、60 秒保持的首末及峰值变化 ≤3°、固定指形转掌期间变化 ≤5°。它不是绝对角度精度验收。有限角度中的预测值、尖峰和大误差均参与统计，不会只挑“正常帧”；缺数据、取消、窗口覆盖不足或缺乏当前观测时不判通过。没有独立真值时，绝对精度与端到端延迟始终为 `not_evaluated`。

稳定的常值输出也可能看似“回位很好”。必须结合实际屈伸、窗间输出幅度及独立角度参考解释报告，不能只看绿色结论。当前界面只做主机时间动作标记，不声称完成物理延迟测量、重复佩戴验证或产品认证。

灰色双骨段表示无效或断流后的最后状态，不是当前测量；橙色表示数据仍新鲜但当前只靠预测，缺少有效角度观测。当前角度可重新观测与历史轨迹完整是两件事，界面分别显示。完全不可观测的运动仍可能漂移，模型协方差不是真实精度界。

无硬件检查入口（不会打开预填串口）：

```bash
QT_QPA_PLATFORM=offscreen vt-glove-pose hinge-live --smoke-seconds 2
```

## 新路线：自然运动标定与离线角度回放

这是独立实验链路，**不要求旧 A/B 成功，也不要求固定近节再单独弯末节**。它允许两块 IMU 都运动，从关节约束估计两根轴，再结合加速度和一段明确的静止参考建立功能坐标，最后运行相对角估计器回放角度。该离线命令不接管旧全手实时 GUI，也不改变其标定文件；新版独立实时实验入口见上一节。

约束是两节点绕同一近似铰链运动时，陀螺角速度在各自关节轴法平面内的模长一致。实现为本项目独立编写的 NumPy 求解器，参考 [Olsson 等的关节轴估计论文](https://doi.org/10.3390/s20123534)。没有复制 qmt 或论文作者的软件；这不是论文完整算法复现，也不能将论文中其他部位的精度当成手套精度。

### 1. 准备三段数据

使用本工具的原始 CSV 或诊断 JSONL。默认节点为拇指近端 **5**、远端 **6**；也可显式指定其他同线路分组的节点对。三个文件名只是示例，不是仓库附带的真机数据：

| 文件 | 内容 | 建议动作 |
| --- | --- | --- |
| `neutral.csv` | 明确声明的静止参考，建议 5 秒 | 轻松保持同一参考姿势，不自动假定解剖学完全伸直 |
| `natural_motion.csv` | 标定运动，建议 20 秒 | 缓慢屈伸目标关节，同时轻缓改变整掌朝向，包含不同转动方向；两骨段均可动 |
| `validation.csv` | 独立验证运动 | 数次屈伸、保持弯曲、回到同一实体参考姿态，并转动整掌 |

静止检查至少需要 2 秒名义采样数据，但安静且接近 1 g 不能证明没有线性加速度或参考姿势绝对正确。自然运动不能只有整掌共转、不能只保持近节固定，也不能仅绕一根轴转掌；这些情况下某些轴自由度无法确定。不要为通过标定快速甩手。标定失败时保留报告，不需要反复尝试同一个失败动作。

### 2. 生成独立的离线候选

安装后在数据所在目录执行：

```bash
vt-glove-pose calibrate-hinge neutral.csv natural_motion.csv \
  --config glove_config.json --proximal 5 --distal 6 \
  --output thumb_offline_profile.json
```

默认取静止文件前 5 秒、运动文件前 20 秒；时间范围相对于各输入的首条原始样本，使用的是主机解析时间。可用 `--neutral-start-seconds` / `--neutral-duration-seconds` 和 `--motion-start-seconds` / `--motion-duration-seconds` 指定已知动作窗口；不会从长日志中自动挑一段“看起来最好”的中立姿势。

输出包含静止偏置、关节轴、功能坐标和各阶段状态。只有 `profile_status=offline_candidate_ready` 才能执行下一步。这个状态表示离线候选已建立，不表示真机精度或产品验收通过。

### 3. 回放另一段运动

```bash
vt-glove-pose replay-hinge validation.csv \
  --profile thumb_offline_profile.json --output thumb_angles.json
```

回放默认使用候选文件中的节点、单位和名义采样率。若另外提供 `--config`，其单位和采样率必须一致。输出 `series` 包含每对样本的 `angle_deg`、`rate_dps`、`quality`、重力纠偏状态、历史丢失标记和主机间隙；`summary` 包含样本量、状态计数、范围及末值。

角度零位来自独立的 `neutral.csv`，不是回放首帧；首帧弯曲时会尝试从当前可观测重力初始化实际相对角。如果首帧重力不可用，报告 `initial_gravity_unobservable`，不会把该姿势偷偷设为零。

当前离线输出的正方向是规范化近端轴定义的**数学方向**，尚未确认解剖屈曲正负。因此弯曲显示负数不等于左右手错配；独立 `hinge-live` 窗口另有显式首次屈曲方向步骤，不改变这里的数学角定义。该命令输出 JSON，不打开 3D 窗口。默认 `--observer baseline` 仍使用现有陀螺预测／条件重力纠偏估计器。

### 4. 对照实验性抗漂移观察器

新候选同时估计相对角度和残余陀螺偏置。除了条件重力，它还在两路横向角速度足够大、满足铰链关系时利用其相对方向约束关节角。没有可用观测时继续预测并标记不确定；不自动把静止或弯曲姿态设成直指。

```bash
vt-glove-pose replay-hinge validation.csv --profile thumb_offline_profile.json \
  --observer constrained --output thumb_candidate_angles.json
vt-glove-pose compare-hinge validation.csv --profile thumb_offline_profile.json \
  --output thumb_comparison.json --html thumb_comparison.html
```

`compare-hinge` 用**同一输入、同一离线标定、各自独立的状态**运行旧观察器和新候选。用浏览器打开 HTML 即可看角度曲线和差值；页面完全离线，不加载外部脚本或上传数据。没有真实角度参考时，差值不叫“精度提升”，更平滑或更接近零也不代表更准确。JSON 保留完整样本；HTML 对长曲线保留分桶极值以控制大小，不通过抽点隐藏短时大偏差。

新候选补充以下字段：

| 字段 | 使用方式 |
| --- | --- |
| `relative_bias_dps` | 估计的两路相对残余偏置，不是每块 IMU 完整三轴偏置 |
| `observation_sources` | 本次采用 `gravity`、`transverse_gyro` 或两者；空列表表示预测 |
| `current_angle_observed` | 当前是否有通过检查的角观测，不代表解剖精度已验证 |
| `time_since_angle_observation_s` | 距离上一次接受角观测的名义处理时间 |
| `angle_std_deg` | 滤波模型标准差，**不是实测误差界或精度保证** |
| `observation_rejection_count` / `rejection_counts` | 观测被拒绝的样本数和各原因计数 |
| `history_loss` / `history_loss_causes` | 已知缺对、陀螺削顶或大幅重新定位留下的历史不确定性 |

短时加速度异常被正确拒绝后，观测恢复可以重新进入 `tracking`，不会仅因此永久标记历史丢失。发生真正缺对或削顶后，即使 `current_angle_observed=true`，历史损失也仍保留；`uncertain` 保留这一历史提醒，不能将它与“当前没有任何角度观测”混为一谈。快速重新观测只恢复当前角度，无法补回丢失的运动过程。

新观察器尚未默认接入实时 GUI，噪声及门槛属于实验参数，未验证真机长期漂移。两个观测源同时缺失时仍可能累积较大误差；持续且与重力无法区分的线性加速度也不能被软件完全排除。

### 无硬件复现新旧算法对照

```bash
vt-glove-pose benchmark-hinge --output observer_benchmark.json \
  --html observer_benchmark.html
```

这会运行九个预先固定的**合成**场景：20 次屈伸、60 秒弯曲保持、共转、暂时不可观测、线性加速度扰动、陀螺削顶恢复、1 g 方向假跳变、仅横向陀螺可用、长期不可观测。解析运动提供参考角，所有帧（包括不确定和削顶阶段）均参与误差统计。恢复时间采用“误差连续 0.5 秒保持 ≤2°”的规则，只是合成场景的软件指标，不是传感器或 GUI 的端到端延迟。

可用 `--cases bent_hold_bias saturation_recovery` 指定场景，`--seed` 固定噪声种子，`--sample-rate-hz` 在 30–240 Hz 之间检查数值采样行为。默认 JSON 仅含统计；`--include-series` 或 `--html` 会包含完整曲线。JSON 与 HTML 必须使用不同的新文件路径，都不会覆盖旧结果。此命令不打开串口或改动任何设备配置。

### 只估计轴，或分析已有配对存档

```bash
vt-glove-pose fit-hinge natural_motion.csv --config glove_config.json \
  --proximal 5 --distal 6 --output axes_report.json
vt-glove-pose fit-hinge paired_capture.npz --archive-prefix a1_ \
  --output archived_axes_report.json
```

`fit-hinge` 不自动估计偏置；原始 CSV / JSONL 可用 `--proximal-bias-dps X Y Z`、`--distal-bias-dps X Y Z` 提供已知偏置。NPZ 中的 gyro 数组按原样使用，禁止再次指定偏置，避免对已减偏置的历史存档减两次。NPZ 必须包含 `node_ids`、`sample_rate_hz` 及所选前缀的 `prox_gyro_dps` / `dist_gyro_dps`；若没有对应 `raw_prox` / `raw_dist`，近量程判断明确为未知。历史 `trim_mask` 不参与筛选。

| 状态字段／值 | 含义 |
| --- | --- |
| `result.candidate_status=candidate_supported` | 轴候选通过当前实验一致性检查；两根轴的正负和零位仍未建立 |
| `insufficient_excitation` | 静止、共转或运动不足，不能确定两根轴；不是程序崩溃 |
| `inconsistent` | 输入不支持当前约束和实验阈值，查看训练／验证残差 |
| `profile_status=frames_sign_unobservable` | 重力沿轴分量不足，无法确定两路轴的相对正负 |
| `profile_status=frames_neutral_unobservable` | 静止参考中轴接近重力方向，无法建立可观测零位 |
| `input_near_limit` | 原始数据接近 int16 量程，换算法不能恢复削顶运动 |
| `replay_status=completed` | 完成数据回放；仍须检查 `quality`、`history_loss`，不是精度验收 |

这些命令正常产生诊断报告时退出码为 `0`，包括候选被拒绝的情况；自动化流程必须读取相应状态，不能只判断退出码。输入格式错误或输出路径已存在时返回 `2`，不会覆盖文件。

CSV / JSONL 默认最多读取 **64 MiB**、最多提取 **10,000 对**，取先达到的限制；可用 `--byte-limit` 和 `--max-pairs` 调整，实验链路最多 30,000 对。报告中的 `stop_reason`、读取字节数和哈希说明实际读取范围，不能把有限前缀当成整个会话。主机间隙不被换算成设备积分周期；发现丢弃配对或明显主机间隙时回放标记历史不确定，不补造样本。没有设备时钟和序列号仍然无法识别所有缺样。

轴拟合的多初值选择只使用预先分块的训练数据，剩余块用于评估；相邻块不是独立会话。`calibrate-hinge` 另外使用整个标定动作的加速度确定轴相对符号，因此最终角度验证必须使用另一段运动。这些检查的阈值是实验设置，不是行业或产品验收标准。

## 拇指弯曲抗漂移：新版使用流程

目标是改善反复屈伸后的**两段相对弯曲角**，不是自动把不动的手指拉直，也不是替整个手掌提供绝对航向。当前实现基于近似铰链模型：两块 IMU 应分别刚性固定在同一个指间关节的两侧；如果安装在不同解剖部位、布料滑动，或做复杂对掌运动，该模型可能不适用。

### 一次联合标定，再验证回正

1. 加载与你当前右手映射匹配的旧标定可以保留其他部位；确认佩戴并完成本次 **静止 5 秒 / 重新归零**。这是显式基线，不会在之后静止时自动重复。不得使用历史诊断检查点作为新一轮硬件的零位。
2. 点击 **① 拇指 A：准备 3 秒 → 采集 8 秒**，或在功能轴下拉框选择 **拇指 A · 先做：固定形状转掌** 后点击“开始所选功能轴”。先显示 **3 秒准备倒计时**，此时不采集标定动作；出现采集提示后，保持拇指形状不变，轻缓地上下翻掌、左右转掌 8 秒，让两块拇指小板一起转动。至少包含两个不同的旋转方向，不能只绕单一方向摆动；不要为了“活动量”用力快速摆动。A 只建立两路传感器坐标关系，不改当前有效安装轴。
3. 看到 A 通过，再手动点击 **② 拇指 B：准备 3 秒 → 采集 8 秒**，或选择 **拇指 B · A 成功后：扶近节屈伸末节**。在 3 秒准备期间，用另一只手轻轻固定拇指近节，不压小板或拉线；提示开始采集后，仅让末节先弯曲、再伸直，轻缓重复 8 秒。不要先反向伸展，不要同时转掌或做对掌动作。B 将一个共同关节轴映射到两个传感器，而不是分别猜两根轴。A 通过不会自动开始 B。
4. B 成功后，新轴只写入内存，立即供估计器使用；失败保留此前有效轴，且不会改为猜测性自动归零。A、B 之间不要重贴小板；重新归零、加载标定或连接中断会清除未完成的 A，须重新采集 A。
5. 检查正常屈伸正负方向，做 20 次缓慢往返，再保持弯曲数秒、保持形状转动整掌。需要记录时，手动开始诊断并标记 `moving` / `returned`；`returned` 是人工标记，不是自动检测到真实伸直。
6. 验证满意后手动另存标定 JSON；不覆盖旧文件。重新连接仍需做本次静止归零；安装未变且保存了联合轴时不必每次重做 A/B。

联合标定每段最多保存 2,000 组配对观测，默认 120 Hz、8 秒在此范围内。高采样率调用若超过此上限会明确拒绝本次标定，不会静默抽样或产生无法导出的诊断状态；不要修改名义采样率来伪装实际设备速率。

旧的独立“拇指”轴标定标注为 **旧版**，仅保留作对照，不证明两路轴一致；拇指抗漂移应使用联合 A/B。新算法发现中立重力与共同轴假设不一致时会明确显示“参考轴不一致，需要联合 A/B 标定”，而不是无提示退回旧 IP 算法。

### 标定总是不通过时，先看数据，不要盲目重做

改进版界面使用显式版本 `robust_v2`。准备倒计时可取消；准备结束会重新检查连接、零位与全部 12 路新鲜数据，不会在断流后偷偷开始采集。准备期间不能同时启动另一次标定、加载、保存或切换配置。倒计时只用于新联合 A/B，不改变旧轴标定及历史重放的动作窗口。

采集中显示 **近 0.5 秒质量提示**：A 显示两路旋转速度相近的样本比例，B 提示近节是否稳定；近量程会单独提示。这些是实时指导，不是最终“通过”承诺，最终判定还要检查整段数据、多方向激励、拟合残差及重力一致性。界面提示的速度比例也不能单独证明传感器实际同步。

完整动作说明可通过“查看详细动作说明”展开，当前准备/采集提示始终显示。长失败原因在结果区域内滚动查看，也可选择复制或悬停查看全文；不会为显示长错误把窗口撑出笔记本屏幕。

- A 不再因为一个非饱和的短暂异常样本，直接把整轮解释成“你没有固定好”。新流程从连续可靠片段估计两路坐标关系，限制可剔除的比例，并使用预先划分、未参与拟合的时间块验证结果。持续不一致仍会拒绝，不能仅挑少量好看的点制造成功。
- A 失败信息给出实际统计和要求。不一致可能来自拇指微动、小板随布料移动、两路量程/单位差异或实际采样时序；程序不能只根据速度幅度把原因认定为用户动作。收到同样错误多次时，应保留原始诊断数据先分析，不必一直归零或重复动作。
- B 仍需固定近节、仅末节屈伸；第一次连贯动作决定轴的正负。准备倒计时把扶稳动作与正式采集分开，**不会把已经采到的第一次屈曲裁掉、再用回程猜正负**。B 失败且连接与佩戴未改变时，已通过的 A 保留，可只重试 B。
- 近量程、断流、无效输入、持续的坐标/重力不一致仍然拦截；不会自动改固件量程、重排传感器样本、根据最优相关性偷偷平移数据，或把当前弯曲姿态设成直指零位。

当前运行中的旧窗口不会因源文件修改自动升级；需要显式重启程序才使用新界面。重新连接后的归零要求仍然适用，不能把离线诊断检查点注入真机延续旧零位。

### 估计器如何处理异常

- 每对新样本按配置名义采样周期积分屈曲角速度差，界面刷新和 USB 同批时间戳不作为积分周期。
- 加速度接近重力、关节轴与重力方向足够不平行、两路轴重力分量及离轴运动一致时，使用相对重力投影修正角度。陀螺仪提供即时运动响应，纠偏不等于把整个运动延迟若干秒。
- 关节轴接近竖直或存在动态加速度时，只显示带“不确定”标记的预测；不会把弯曲手指突然画成中立直指。`ip_valid` 表示数值可用，**`ip_confident` / `ip_estimator` 才描述纠偏状态与可信度**，不能只看 `valid` 判断精度。
- 近量程、已知失配会留下 `history_loss` 记录，其他节点和原始采集继续。可信重力恢复后可以有限速重新约束**当前**角度；这不恢复此前丢失的运动轨迹，历史损失标记仍保留。大误差恢复可能需要数秒，不能将这种恢复过程当作正常跟手延迟指标。
- 静止时仍保持真实观测到的弯曲角，不假设“静止=伸直”。加速度约 1 g 也不是没有线性加速或模型必然正确的证明。
- 真实陀螺仪饱和必须核实固件量程。只改 Python 单位比例、丢弃触顶样本或扩大显示范围都不能恢复丢失数据；本程序不会向设备发送量程配置或刷写命令。

新版诊断使用 engine checkpoint v2，明确记录 `thumb_paired_gyro_gravity_v1`、估计器状态、配对进度及未完成的 A。旧 checkpoint v1 明确恢复 `legacy_quaternion_v1`，不会拿新算法假称精确重现旧日志。诊断 JSONL 外层事件格式仍为 v1；普通标定 JSON 不保存实时积分状态。

新联合命令另外记录 `calibration_method: robust_v2`，未完成的 A 检查点也保留该方法，A/B 不允许混用不同方法；没有该字段的历史联合命令仍按原来的 `strict_v1` 重放。准备倒计时不算采集事件，记录的是实际开始时刻。读取新方法记录需要支持该方法的代码版本；旧版本不得用旧算法冒充重现新结果。

首轮真机建议验收目标（**尚非已达到的精度承诺**）：20 次往返同一实体参考姿态的回正偏差 ≤5°，固定拇指形状转掌的假屈曲变化 ≤5°，固定姿态 60 秒的相对角变化 ≤3°。必须分别报告动作速度、触顶次数、低可观测区间、回正误差和静止变化；合成测试通过、输出接近零或重放一致均不能替代真实姿态参考。

## 真机标定：每一步均手动开始

先选择左右手、勾选左右手确认，并核实配置。连接后再加载需要复用的标定文件；若启动时指定了 `--calibration`，程序会在手动连接成功后加载它。首次使用直接从静止归零开始。各步失败时查看提示并重做，不要为了让骨架变彩色而绕过未通过的项目。

1. 确认佩戴：固定小板，检查候选手掌参考 Node 12 是否贴合且不会随布料滑动。平放手掌，手背向上、手指自然伸直，记录这次约定的拇指和手指张开姿势。勾选界面的佩戴确认框。
2. 静止 5 秒：点击“静止 5 秒 / 重新归零”，全程不要屈伸、碰板或移动。程序检查各路样本量、静止程度和约 1g 的加速度，估计静止陀螺偏置，再用新偏置重放通过检查的静止样本，为各节点重建滤波历史及本次零位，避免旧偏置的积分和滤波残留被当作手指运动。这是一次新的姿态参考，不保证手动归零前后的姿态连续；无需额外操作。任一路失败都不会保存半套新零位。
3. 手掌功能轴 8 秒：选择“手掌参考”，保持五指伸直，先做轻柔的手腕向下屈曲，再回到原位，重复约 3–4 次。不要先向上伸展；第一次有效运动用于确定轴的正负方向。这里是给手掌 IMU 建立局部轴，不是在测量腕关节角。
4. 食指、中指、无名指、小指功能轴 8 秒：逐根选择目标，保持手掌稳定，让整根目标手指先向掌心弯曲、再伸直，重复约 3–4 次，使这根手指的两块板均产生清楚的屈伸运动。不是只动最末端关节；也不要靠摆动整个手掌代替手指运动。**拇指使用前文的联合 A/B，不套用本条四指动作要求。**
5. 检查方向并再次归零：回到相同平手姿势，观察屈曲方向是否正确，完成需要的功能轴后建议再做一次 5 秒静止归零。若反向、侧摆异常或不合理地触发角度裁剪，先排查安装、动作方向、单位和映射。
6. 手动保存 JSON：有效零位存在且没有进行中的标定时，点击“保存标定 JSON”，选择新文件名。程序允许保存部分功能轴尚未完成的文件，因此“保存成功”不表示完整标定通过；未完成部位仍应保持无效状态。

功能轴估计依赖陀螺运动的主要方向与静止重力方向；它会拒绝活动不足、手掌连带运动过大、轴不明确或几何退化的采集。轴方向的正负由未裁剪采集窗口中的首段连贯屈曲确定，不能忽略较快的第一次屈曲后把回程当成正向；首段方向含糊时会拒绝本次标定。拇指真实运动复杂，可能不满足这版单主轴假设，从而未通过轴检查。出现这种情况就保留为未标定，不能把其他手指的轴、任意单位轴或合成演示结果替代成拇指标定。

静止归零不等于安装轴标定。姿态滤波器输出一个四元数，也不意味着已经获得了可信的解剖坐标轴。

### 保存、加载与重新连接

标定 JSON 保存静止偏置、传感器到骨段的安装旋转及配置指纹等信息，不把上一会话的零位四元数当作下一次可用零位。加载文件后必须重新确认佩戴并做本次静止归零；保留的安装轴仅适用于配置相同、且小板相对骨段没有重新安装或滑移的情况。

2026-09-28 食指 / 无名指映射纠正前后的配置指纹不同，旧配置或旧标定不能与新配置混用，也不能只改指纹绕过检查。本次实验的受控迁移仅可保留未受此次映射纠正影响、且安装未变的 Node 5/6/12 安装轴；不继承食指 3/4 或无名指 7/8 的旧轴，也不恢复旧会话零位。迁移结果应另存新文件并记录来源，旧文件和日志保持不变。加载新配置及迁移文件后，仍须确认佩戴并重新完成 5 秒静止归零；这不是自动通用迁移规则。

功能轴符号算法修订为 v2，文件按节点记录 `axis_sign_versions`。旧版或没有该记录的轴仍可加载，但界面会警告其方向可能受旧版首段裁剪问题影响，建议重新做受影响的功能轴标定。仅重新归零或另存旧文件不会把旧轴自动升级为 v2，也不会修复轴方向。

`live` 和 GUI `replay` 的 `--calibration PATH` 会在用户手动连接或开始回放时加载文件，不自动连接、不自动归零。没有指定该参数时，顺序是手动连接或开始回放 → “加载标定 JSON” → 本次静止归零；未连接时不允许手动加载。连接会创建新的处理会话，重新连接后会重新加载启动参数指定的文件；其他手动加载的文件需要按界面状态重新加载。无论哪种方式都需要本次归零。采样中断导致零位失效时，安装轴保留，但仍需重新归零。

```bash
vt-glove-pose live --config glove_config.json --calibration hand_calibration.json
```

文件只创建、不覆盖。标定过程中可以点击“取消标定”，失败或取消不会把本轮不完整结果当作成功标定。

## 如何读界面

拖动模型改变观察视角，滚轮缩放，双击复位；这些操作只改变观察视角，不改变测量坐标。实体模型表现手掌厚度、圆润指节、指尖和腕部轮廓；这只是示意几何，不是扫描得到的个人手型。整体朝向由姿态数据驱动，鼠标视角旋转与真实手掌旋转是两件不同的事。

- “显示方式”默认选择“实体 3D”，切到“骨架调试”可检查骨段和推算末端。
- 顶部明确标明配置的“右手 / 左手”与当前“手背朝向你 / 手心朝向你 / 侧面视角”，不是传感器自动识别手别。手背为浅色且有指甲，手心为同状态下较深的青调；未标定仍蓝灰、断流仍红色，不会因美化变成有效姿态。
- “看手背 / 看手心”将观察相机对准当前模型对应的一面，只改变视角，不切换左右手、不重置归零或标定。开启整掌跟随后，之后的真实转掌仍会改变朝向；侧面不强行标作手心或手背。未归零时标为“参考外形”，断流时标为“历史画面”。
- “整掌朝向跟随”默认勾选；取消勾选会锁定手掌局部坐标，便于单独检查手指相对屈伸，并不会重新归零或改变滤波。
- 实体视图区分有效、不确定/推算、未标定和断流状态，并保留推算末段标记。形状完整不意味着所有角度已经可用，仍须结合右侧表格和状态提示判断；浅色材质不是“已经通过精度验证”的标志。
- 指根和指间关节用高对比关节环突出位置，方便观察弯折中心。关节环是模型定位提示，不代表增加了关节传感器或直接测得关节中心；四指末端 DIP 仍须与推算/未观测状态区分，拇指仍只标示暂定的 MCP / IP。
  正常可显示时，指根 MCP 为深青色，中间 PIP / 拇指 IP 为浅青色，启用且有效的 DIP 推算为金色；禁用或不可用的 DIP 为灰色。断流、无效或角度越界时，红色、灰色或金色告警优先，因此金色也可能表示越界，须结合表格与提示判断。

“功能轴 N/6 完成”逐项显示手掌与五指进度；一根手指的两块板都通过才算完成。
悬停可查看具体节点，Node 11 辅助节点不计入默认配置的六项功能轴。

- 灰色中立模型是未归零、缺少安装轴或其他无效条件下的占位形状，不是测得的“手已伸直”。断流、断开及回放结束均应结合状态栏识别，不把最后的几何当作仍在实时更新。
- 四指显示 MCP、PIP 和侧摆；DIP 带推算含义。拇指显示暂定 MCP / IP / 侧摆，没有 PIP 或 DIP 测量。
- 手掌失效时 MCP / 侧摆不可用；若该手指两路仍新鲜且安装轴有效，其相对 PIP / IP 仍可单独计算，整根手指的完整骨架仍标为无效。表格中的 `—` 表示不可用，不是零度。
- 超出模型显示范围的角会被裁剪并产生告警。裁剪只限制不合理的显示，不会修复错轴、软组织滑动或漂移。
- “接收 Hz”是基于主机收到样本的时间统计。同一 USB 批次的多条样本可以有相同时间，不能把这一列当作已经校准的设备采样率。

## 原始录制、检查与回放

实时模式连接后，点击“手动录制原始 CSV”，选一个不存在的路径；点击“停止录制”关闭文件。录制仅保存收到的原始 IMU 数据，不自动保存标定、不输出临床或产品级关节测量报告。建议让实验记录包含明确的静止段、功能动作段、所用配置、佩戴说明及单独的标定文件。

支持的是长表 CSV，每行一个节点样本，所需表头为：

```text
host_parse_monotonic_s,host_parse_wall_s,node_id,gx_lsb,gy_lsb,gz_lsb,ax_lsb,ay_lsb,az_lsb,status
```

`status` 可省略；兼容的映射日志还可有 `phase` 列，该列仅为实验阶段备注，不参与姿态计算。其他列必须齐全，字段不能重复；额外未知列会被拒绝。节点为 `1..12`，六个原始值均为有符号 16 位整数。单节点的主机单调时钟时间不可倒退，但可以相等。

这两个时间都是主机解析时间，不是设备采样时间。线路帧每组 84 字节、含六个 14 字节节点块，节点组为 `1..6` 或 `7..12`。解析器检查节点排列进行同步，但协议没有可用的校验和、序列号或设备时间戳；同步通过不能证明载荷未损坏，也不能精确还原丢样或设备时钟。

已有临时映射原始 CSV 在表头和值符合上述格式时可以直接读取。普通 `Ploy_IMU.py` 宽表 CSV 并不自动兼容；不能只改扩展名或表头就当作同一种数据。

```bash
vt-glove-pose inspect imu_raw.csv --config glove_config.json
vt-glove-pose inspect imu_raw.csv --config glove_config.json --output raw_report.json
vt-glove-pose replay imu_raw.csv --config glove_config.json
vt-glove-pose replay imu_raw.csv --config glove_config.json --calibration hand_calibration.json
vt-glove-pose replay imu_raw.csv --config glove_config.json --headless
vt-glove-pose replay imu_raw.csv --config glove_config.json --headless --output replay_result.json
```

`inspect` 输出每节点记录数、主机接收速率、原始值统计、按假定比例换算的加速度模长及相关告警，不代表姿态精度评估。`inspect` 以及无头 `demo` / `replay` 默认打印 JSON，指定 `--output` 则只创建新的 JSON 文件、不覆盖；GUI `demo` / `replay` 不能使用 `--output`。

GUI 回放需要手动点击“开始回放”，按记录中的主机时间节奏读取，滤波仍按配置的名义采样周期推进；没有把 USB 到达间隔当作每次积分时长。无头回放不按墙钟等待，按记录顺序处理并输出最后一帧历史快照。到文件末尾会明确标为回放结束，不会伪装成持续在线设备。GUI 停止后可以重新开始回放。

旧 CSV 若没有可用的佩戴标定和足够的中立/功能动作片段，不能自动得到完整可信的手姿。加载安装轴仍不能替代本次零位；GUI 只有在回放包含相应窗口、并由操作者按已知阶段手动触发标定时才可能恢复这些条件。`--headless` 不会自动猜测零位或动作阶段。原始回放不是合成 `demo`，无效姿态保持不可用是预期行为。

## 记录漂移／回正慢现场并离线复现

原始 CSV 适合检查码值，但在程序运行中途开始录制时，仅有 CSV 和安装标定 JSON
不足以还原当时的 VQF 滤波历史及本次零位。新增的**诊断会话 JSONL**专门保存这些现场信息；
它与普通 CSV 录制独立，不改变融合参数、不替代标定，也不自动连接设备。

### 真机上如何使用

1. 正常手动连接，在现有姿态状态下点击“开始诊断”，选择一个**不存在的 `.jsonl` 文件**。
   不需要为了开始记录而重做整套标定。正在进行静止或功能轴采集时，请等它结束或手动取消，
   再开始诊断；未归零或缺少轴标定也可以记录，但不会因此得到有效手姿。
2. 先静止约 3–5 秒，选择“静止”并记录标记；开始屈伸时记录“运动”；实际恢复伸直时记录“已伸直”，
   随后再保持约 5 秒。标记只是人为备注，点击有反应时间，**不能作为精确同步的真实运动时间**。
   可在一次录制内逐指重复，不必断开设备或反复重启。
3. 点击“停止诊断”，等待状态从“停止中”变为“完成”后再分析文件。
   断开数据源或正常关闭窗口也会请求结束诊断；为避免程序退出打断缓冲写入，建议先手动停止并等待完成。
   异常退出、写满磁盘或队列溢出可能留下不完整文件，原始可读前缀仍可分析。
4. 在另一个终端离线生成报告：

   ```bash
   vt-glove-pose diagnose-session glove_diagnostic.jsonl --output glove_diagnostic_report.json
   ```

没有 `--output` 时打印报告；报告也只创建、不覆盖。命令不连接串口、不打开 GUI、不执行录制中的文件路径。
会话自带配置，无需另传 `--config`。诊断按钮在 demo 和普通 CSV 回放模式中隐藏。
当前诊断会话提供**无头重算与报告**，不是新的 GUI 播放格式；原有 `replay raw.csv` 的用法不变。

### 报告如何判断

| 字段 | 可以说明什么 |
| --- | --- |
| `session_complete` | 是否读到连续序号、合法末尾完成标记，且没有结构错误；不是硬件无丢包证明 |
| `reconstruction.status` | `match`：重算与记录一致；`mismatch`：存在差异；`unverified`：数据不完整、版本不符或未重算 |
| `nodes` | 各路码值统计、接收频率、相同主机时间、断流间隔及接近 int16 极限的记录数 |
| `host_metric_peaks` | 串口待读字节和处理耗时峰值等主机侧指标；不是传感器端到端延迟 |
| `recorded_pose_statistics` | 已记录估计角的范围、有效帧数、显示角度裁剪帧数；不是解剖角准确度 |
| `markers` | 人工动作备注在事件序列和原始样本中的位置；最多保留 128 条明细，超出单独计数 |

默认退出码：`0` 表示文件完整且有原始数据和姿态快照、重算一致；`1` 表示报告已生成但未通过完整复现；
`2` 表示输入头部、文件读写或命令参数错误。`match` **不等于解决了真机漂移，也不代表测量精度合格**。
没有真实同步参考时，报告不会给出“真实手指回正延迟”或准确度数值。

若当前 VQF 版本与会话不一致，默认仍给出原始统计，但不会宣称精确复现成功；可明确跳过重算：

```bash
vt-glove-pose diagnose-session glove_diagnostic.jsonl --raw-only --output raw_only_report.json
```

`--raw-only` 的退出码 `0` 仅表示会话结构完整，`reconstruction.status` 仍是 `unverified`。
精确复现请使用录制时的 VQF 版本与匹配的工具代码，报告比较模型、节点、标定状态及计数，
不比较保存路径等提示文案。当前格式没有工具代码的加密签名或数据校验和。

### 数据范围与故障行为

- 文件包含初始离线 checkpoint（配置、安装轴、本次零位、VQF 版本／参数／状态）、
  有序原始样本批次、成功的归零／功能轴／取消操作、加载后的 checkpoint、姿态快照时钟、主机指标和人工标记。
  合法的 VQF 初始化 NaN 哨兵使用受限标记编码，不将它们改成零，也不允许原始样本含非有限值。
- checkpoint **只能创建离线重算实例**；不会通过普通“加载标定”恢复旧会话的实时零位。
  普通保存／加载标定的要求保持不变：重新连接／加载后仍需本次静止归零。
- 独立有界写入队列，采集端不等待每批磁盘写入。队列满或写入失败停止诊断并提示错误，
  不断开串口、不丢弃采集数据以假装录制完整。停止中的 writer 未退出前不能重复启动。
  诊断有复制和序列化开销，不承诺零性能影响；原始 CSV 的同步写入行为没有被本功能改变。
- 完成标记只表示应用顺序写入结束，不是 `fsync` 持久化、断电恢复或真实传输完整性的保证。
  操作系统严重 I/O 故障也可能使失败后的标记回退失败；以界面错误和报告共同判断，不把文件存在当作成功。
  分析程序有单行 2,000,000 字节及批次大小等上限，非法、截断、重复键、序号断裂或未知事件会明确报错。
- 诊断保存的是**解析后的码值**，不是完整 USB 线路字节包。会话可能包含本机时间、佩戴标定与操作信息；
  分享文件前自行检查。软件不自动上传诊断数据。

## 排查顺序

先看数据，再看单位与时序，最后看模型。一直没有骨架运动时，不要先调显示比例。

1. 核对串口路径、权限、占用程序及 12 路数据完整性；不要同时运行两个串口读取器。
2. 查看静止加速度是否符合约 1g、陀螺是否接近静止，核对固件量程和名义采样率。不能为了通过静止检查而随意改比例。
3. 确认本次零位有效，所需手掌和指骨安装轴已通过功能标定；加载旧文件之后是否忘记重新归零。
4. 检查实际板位、正向屈曲的第一动作、手掌固定、左右手和个体尺寸。拇指失败可能是模型假设不适用，不一定是“动作不够大”。
5. 遇到 Qt 显示环境错误，可先跑 `demo --headless`；离屏 Qt 检查使用上面的 `QT_QPA_PLATFORM=offscreen` 命令。无头运行通过不证明桌面驱动或真实设备正常。

### 漂移、回正慢和显示卡顿不是同一个问题

- **整个手掌不转动**：检查是否选择跟随手掌朝向的视图，以及手掌参考的归零、功能轴和数据有效性。局部视图会主动抵消手掌的公共旋转。
- **画面更新慢**：查看主机串口待读字节数及处理耗时。界面只保留最新快照，不排队播放历史姿态；但如果读取、原始录制或融合处理来不及，串口端仍可能积压。主机解析时间不能证明数据此前没有等待。
- **画面流畅但手指回正慢**：查看角度裁剪告警，并核对陀螺量程、名义采样率、安装轴正负及候选手掌参考固定情况。角度达到显示上下限后会被裁剪，底层估计未回到范围内时可能看起来暂时“卡住”。不要通过加重平滑或强制自动伸直掩盖原因。
- **缓慢航向漂移**：六轴 IMU 没有绝对航向观测；模型更逼真不会补齐这一信息。不同节点的相对漂移仍需真机验证，后续若引入外部方向约束，需要独立设计和验证。

VQF 默认 `tauAcc=3 s` 是加速度校正的滤波时间常数，**不等于整个姿态输出固定延迟 3 秒**。正确、同步的陀螺与重力输入可快速跟随屈伸；若陀螺比例、时序或方向不一致，慢速校正可能表现为动作之后继续变化。参数定义见 [VQF 参数文档](https://vqf.readthedocs.io/en/latest/ref_cpp_params.html)。本工具没有通过随意调小时间常数来宣称已解决真机漂移。

运行时快照 `runtime.performance` 保存有界的主机诊断计数与耗时，包括最近读取前后待读字节数、单批样本量、读取/融合/录制/快照构建耗时，以及主机发布时刻；它不是原始数据录制，不会自动保存文件。这些字段的时间基础是 `host_observed_not_sensor_latency`，不包含设备内部采样到 USB 接收之前的时间，不能当成端到端传感器延迟。
