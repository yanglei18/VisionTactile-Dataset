# 官方 FSGlove 核心与 12 路 IMU 适配工具

**推荐先用 `upstream-check` 检查，再用 `upstream-live` 启动官方模式。** 官方模式实际执行外部 FSGlove checkout 中未改写的 `Raw2MANOCalibrator` 和 manotorch 模型；`upstream-shape` 实际调用官方可微 MANO 触指手形优化。旧 `live`、`calibrate`、`solve` 是本仓库自行编写的实验算法，保留作 legacy 对照，不能当作官方实现。

本工具仍是实验原型：12 路硬件适配不是作者发布的原始 16 IMU 配置，公开代码也不能等同论文全部算法已经复现。真实佩戴的动作准确度、回位稳定性和长期漂移仍待验收。工具不替换 `tools/glove_hand_pose/`，不内置或分发 FSGlove 源码与 MANO 模型。

串口只在窗口中明确点击“连接”后打开；启动窗口、设置 `--port` 都不自动连接，不自动重连、抢占串口或关闭现有程序。检查、形状优化及文件回放不访问串口。

## 标定窗口操作

窗口使用主采集程序的黑灰主题，在同一窗口中提供三个页面，共享右侧三维手形：

- **姿态标定**：连接设备后，依次采集平掌、指尖上倾、指尖下倾，再进行全手弯伸校准。需要补采时展开“单指补采”；采集动作提示、倒计时和取消按钮固定在预览上方。
- **个性化手形**：可选的触指标定、候选优化、预览和采用。“任务与文件”和“结果详情”默认折叠。
- **诊断**：查看逐路 IMU、输入配置、尺度检查、运行统计、节点反馈和完整记录路径。切换页面不会连接设备或启动采集。

窗口底部区分“标定已生效”和“已保存”。记录暂停、保存失败及可用的保存重试操作在各页面保持可见；“打开记录目录”可访问本次文件。关节透视标记位于“显示选项”，默认关闭；启用触觉输入时才显示“触觉叠加”入口。已打开的窗口需正常关闭后重开，才会加载新界面。

标定参考因滤波重置而失效时，首页、预览状态和底部统一提示重新标定；已保存文件仍保留。短暂缺测显示等待有效输入，局部失效单独标注，不把它们都当作全手永久失效。保存状态独立显示：基础标定已保存时，触指任务仍可能未保存。

基础标定文件与触指任务的保存错误会同时显示在全局底部。三个页面共用“重试保存”和“另选保存目录”的操作条件；采集、计算、清除或等待保存应答期间禁止重复提交。后台确认后才清除对应错误，一类保存成功不会隐藏另一类仍未解决的问题。

### 维护与自动化验证

`calibration_presentation.py` 从后台快照生成只读状态；`calibration_actions.py` 统一保存请求与应答跟踪。`live_ui.py` 负责窗口协调，各页面共用这些结果。后台仍负责最终操作校验和实际文件写入。状态刷新不执行采集、优化或文件保存。

独立的 [Glove calibration CI](../../.github/workflows/glove-calibration.yml) 安装 PyQt5 测试依赖并运行手套模块测试，与主程序的 PySide6 作业分离。关键状态与界面测试必须实际执行；除明确不适用于旧模式的两种参数组合外，跳过关键测试会导致检查失败。MANO、ROS 或硬件专项的跳过原因仍保留在测试报告中。

在已安装本工具 `test,live` 依赖及纯触觉传输模块的环境中，可执行同样的检查：

## ROS 2：保留原界面，只发布解算结果

现在支持通过 `--hand left/right` 选择左右手；省略时从 `--config` 读取手别，无配置则保持右手。
手别贯穿官方标定、MANO、形状标定与 ROS 导出；同一代码可分别打开两个独立窗口。
左手需要 `models/MANO_LEFT.pkl`，内置左手 IMU 映射仅为未实测模板，须核对真实安装。
双手、单手、仅手势和仅触觉的组合启动见
[统一 hands.launch.py 操作说明](../../ros2_ws/src/vt_glove_bridge/README.md#22-单手双手和仅触觉统一入口)。
左手触觉贴图需要额外 `--tactile-layout`，不自动把右手布线镜像视为左手标定。

新增可选 [ROS 2 Jazzy 桥接与统一启动入口](../../ros2_ws/src/vt_glove_bridge/README.md)。
`ros2 launch vt_glove_bridge glove.launch.py ...` 默认同时打开原有官方模式标定/三维界面，
并启动独立桥接进程。仍在原界面手动连接、完成三姿势及功能标定；不另开串口，不运行第二套解算器。
不使用 ROS 时，原有独立启动命令保持不变。

默认仅发布 `/gloves/right/state`（`vt_glove_msgs/msg/GloveState`），用于与相机和 Tracker
录入同一个 bag。消息保存同一帧 MANO 姿态、手掌朝向、可用时的 21 关节点、实测/推算标识、
标定版本及质量信息；**不发布原始 IMU、网格顶点或 MANO 模型文件**。既有本地 CSV/JSONL
调试记录保持独立，不会因此被加入 bag。

已单独启动 bridge 时，在原 `upstream-live` 命令末尾增加：

```bash
--ros-socket /tmp/vt-glove-$(id -u)/right.sock
```

该参数只是启用非阻塞的结果出口，不会自动连接设备。必须与 bridge 的 `socket_path` 一致。
传输失败仅累计未送达帧数，在窗口统计区显示；不会重连串口或清空标定。界面中的发送成功
不是 ROS 订阅者或 bag 的接收确认。桥接恢复后发送后续新结果，不积压重放旧姿态。

时间戳取**本帧所用手掌节点的主机接收系统时间**，并保留其他模型输入节点的独立源时间、
样本计数及滤波 epoch。源时间通过整数纳秒传递，计算时刻与 ROS 接收时刻单独记录。
同一次 USB 读取可以包含多包共享接收时间；这不是硬件采样同步，也不证明 12 路同时测量。
旧 CSV 只有浮点秒，没有可验证的整数源时间，不能用当前发布时间将其伪装成实时数据。

默认配置目标为 30 Hz；可用 `--output-rate-hz 120` 请求 120 Hz 解算，已移除原来的 30 Hz 硬上限。
目标频率不是实测保证，实际发布率以新输入的解算输出为准。未标定/无新鲜手掌时发布不可用结果；
断流无新结果时，bridge 报告等待而不伪造心跳姿态。单位未核实、近轨告警、缺测先验和未修复
偏航漂移继续如实标注。ROS 接入不改变当前算法精度。

启用功能铰链估计后，逐关节 `joint_valid_mask`、`joint_display_available_mask`、
`joint_quality` 和 `joint_estimation` 放在 `quality_json` 中，顺序为 MANO 16 槽位。
任一受管理关节降级/不可用，整帧 `pose_valid=false`，但仍可保留当前有限数值数组供明确识别质量的消费者局部使用；
**数组非空不表示有效测量**，不可用槽位可能只是合成网格所需的占位值。
原观测/推断 mask 是来源信息，不替代估计有效性。旧消费者应继续严格检查 `pose_valid`；
新消费者若使用部分姿态，须同时读取上述逐关节质量，不能把占位零位或暂估值作为真值。
`quality_json` 同时包含 `joint_calibration_status`、`functional_calibration_coverage` 和
`joint_output_provenance`：分别表示逐关节校正状态、9 个可做功能标定槽位的覆盖情况，以及
原始/功能适配/缺测先验来源。有安装标定输出，不等于所有关节完成了功能校正；
`reference_coverage=complete` 也不等于当前所有关节可信，更不代表通过人体精度验收。
界面为避免闪烁而保留的历史姿态只用于显示，不会发布为新测量。局部关节使用历史显示值时，
ROS 保留原解算的有效性与源时间，`joint_positions_m` 为空，不导出展示缓存的骨架位置。

坐标以手腕为原点、单位米，轴向为本次标定参考；关键点已经包含手掌根旋转，不能再重复旋转。
这不是 Tracker 世界坐标，也没有测得的全球平移。MANO 16 个轴角槽位与 21 关节点的排序不同，
详见消息注释和桥接 README。离线匹配见[手套专用适配](../multisensor_alignment/README.md#113-当前-fsglove12-解算结果)。

## 在三维手模型上显示 ROS 触觉

`upstream-live` 现在可在原有 MANO 手表面叠加触觉，不另开手模型、不改变界面主题，
也不改变 FSGlove 解算、IMU 标定、串口读取、120 Hz 目标或 ROS 结果内容。
触觉仍由独立采集节点发布；显示桥接只订阅 `/gloves/right/tactile/state`。
该状态、二维视图和三维触觉输入统一为 **20×20 / 400 个有效物理地址**
（`TactileState.schema_version=2`，ADC、有效掩码均为行优先 400 项，逐块时间为 160 项）。
此范围对应原始行列 0–19，直接裁取，不缩放或重新编排地址；发布频率保持原值。

### 安装与启动

已有可工作的手势环境和触觉节点时，在仓库根目录执行一次：

```bash
export VT_REPO="$(pwd -P)"
cd "$VT_REPO"
# 只补装本仓库的纯显示辅助模块；不升级 NumPy、PyTorch 等解算依赖。
.venv-fsglove-120hz/bin/python -m pip install --no-deps --no-build-isolation \
  -e ros2_ws/src/vt_tactile_capture
source /opt/ros/jazzy/setup.bash
cd ros2_ws
colcon build --symlink-install --packages-up-to vt_glove_bridge
source install/setup.bash
```

1. 按[触觉采集说明](../../ros2_ws/src/vt_tactile_capture/README.md#3-一条命令启动采集和热力图)
   启动触觉节点；**已运行时不要重复启动、不要抢占触觉串口**。原二维视图可同时保留。
2. 在原[手势 ROS 联合启动命令](../../ros2_ws/src/vt_glove_bridge/README.md#2-一条-ros-launch-同时打开原界面)
   末尾增加 `tactile_overlay:=true`。其余模型、配置、IMU 串口与解算频率参数保持原值。
   该选项仅增加只读显示桥接，**不自动启动触觉串口采集**。
3. 在手势窗口正常连接并完成 IMU 标定。展开预览下方的“触觉叠加”，松开全部触觉区域，
   点击“采集触觉无载参考（3 秒）”。此操作与 IMU 标定独立，不清除手势标定。
4. 点击“看掌面”，依次按压指腹、掌心和掌根，观察对应皮肤着色；保持按压再弯指、转掌，
   热点应随模型表面移动。“显示选项”中的“关节透视标记”默认关闭。

独立 GUI 启动时，在原命令上增加 `--tactile-socket /tmp/vt-tactile-$(id -u)/right.sock`，
并在 ROS 终端运行 `ros2 launch vt_tactile_capture tactile_display_bridge.launch.py`。
自定义路径须同时指定 bridge 的 `socket_path` 和 GUI 的 `--tactile-socket`。
同一 socket 只能有一个 GUI 接收者；另开窗口需独立 socket 和对应桥接。
GUI Python 无须安装 `rclpy`，不要将 ROS 的 `PYTHONPATH` 注入手势虚拟环境。

已打开的旧窗口不会热加载这些控件。请在方便重新标定时正常关闭、按新命令重开；
不能依靠重启继承内存中的安装标定。未启用时，原手势功能照常工作。

### 颜色、空间与时间的含义

| 项目 | 当前行为 |
| --- | --- |
| 数值 | `当前 ADC − 本窗口无载参考`；有正有负，不是 N / Pa |
| 颜色 | ±200 ADC 保持原掌背本色；负变化为蓝，正变化由黄到红；轻触 ±3000、强响应 ±16000 只改变色限 |
| 映射 | 原始行列 0–19 的 20×20 有效区域；400 个三维位置仍为候选，7 区域、9 个地址锚点已核对，逐点物理位置尚未全部标定 |
| 随动 | 中立网格一次性建立三角面 / 重心坐标绑定；颜色限制在同一手指或掌部的掌侧，不在每帧按空间邻近重绑 |
| 时间 | 同机 `CLOCK_MONOTONIC` 源时间；选择不晚于当前展示姿态的触觉快照，时差最多 150 ms，源年龄最多 250 ms；每个块还遵守采集端有效期 |
| 刷新 | 触觉叠加约 30 Hz，独立于姿态解算频率；不会为凑频率生成新触觉或姿态 |
| 缺测 | 触觉过期、缺参考或无有效对应姿态时恢复原手颜色，不隐藏手；保持／未知手指不叠加新热点 |

这仍是滚动矩阵上的显示级时间关联，**不是硬件同步、不是接触几何精度证明**。
标定动作示意、冻结手形以及历史姿态回放不与实时触觉混画。
触觉采集身份或健康状态发生变化后，本窗口要求重新采集触觉参考。
二维触觉窗口和三维窗口复用相同参考算法，但各自手动采集参考，**不自动共享零点**。
串口和 `/tactile/samples` 仍保留原始 80×80 地址协议，便于旧 bag 兼容与追溯；
这些原始数据包并不代表存在 6400 个有效触觉单元。范围外地址不进入状态、参考或三维着色。
显示桥接／控制器读取旧 `schema_version=1` 的 80×80 状态时会显式裁取左上 20×20，
保持原采集时间与掩码，不把旧数据重新标记为新采集。

如果没有热点，先看该组中的状态文字：确认收到 tactile/state、有有效无载参考、
当前展示是真实新鲜手势而非标定示意，然后查看源年龄和姿态时差。
“没有不晚于手姿态的触觉状态”通常表示姿态尚未更新或两路延迟差过大，
不应通过伪造时间、放宽原始数据有效性或反复清空 IMU 标定来隐藏。

验收时应逐区检查定位、正负响应、持续按压、弯指跟随和断流恢复；
软件／合成网格测试通过不能替代这轮新三维功能的真机验收。

2026-10-06 验证：真实 MANO + Qt + Unix IPC 的合成联调通过，包含未完成 IMU
标定时独立采集触觉参考、食指着色、弯指随动、触觉断流后恢复本色且保留手形；
另通过实际 ROS DDS→显示桥接→IPC 的数值／时间戳保真测试。
独立 Qt/OpenGL 合成预览工具为 [preview_tactile_surface.py](scripts/preview_tactile_surface.py)，
传入 `--mano-assets /可信模型目录 --output-dir /新的输出目录` 可生成掌面、弯指、手背
三张带 SYNTHETIC 标签的图像；它不打开串口或 ROS，也不操作现有窗口。

## 新右手 IMU 布局：显式输入配置

新布局使用 [configs/right_new_imu.json](src/vt_fsglove12/configs/right_new_imu.json)。
默认的 `right_current.json` 继续保留 GitHub 历史基线；选择新配置时仍使用同一套融合、
三姿态标定、功能轴和手形模型，不增加新的骨段推算或自动配置组合。

| 物理位置 | 新编号（靠指尖 / 靠掌端） | 对应旧编号 |
|---|---|---|
| 拇指 | 1 / 2 | 6 / 5 |
| 食指 | 3 / 4 | 4 / 3 |
| 中指 | 5 / 6 | 2 / 1 |
| 无名指 | 7 / 8 | 8 / 7 |
| 小指 | 9 / 10 | 10 / 9 |
| 掌心 | 11 | 12 |
| 手腕外部（辅助） | 12 | 11 |

原始编号、整数值和接收时间戳按原样记录。3/5/7/9 是用户描述的靠指尖传感器，
继续对应旧模型的第二骨段槽位；这里不把安装描述转换成新的解剖模型。
12 号参与原始记录和诊断，不参与手部模型标定及发布参考节点。

新配置显式使用 `0.035 °/s/LSB`、`0.000244 g/LSB` 和 `104 Hz` 名义采样频率，
解算输出目标也是 `104 Hz`。这些是有证据支持、尚待实机验收的候选设置：

- 提供的 STM32 原始源码（`ac22963`）配置为 ±1000°/s、±8g；尚未核实当前设备的烧录配置或寄存器读值。
- 两段已有倾转记录在按 `104 Hz` 计算时，陀螺系数 `0.035` 比 `0.0175` 更符合末端重力方向变化。
  此比较依赖采样时基及重力近似，不能独立确认陀螺倍率与设备采样间隔。
- 低运动片段的原始加速度模长约为 `4113～4264 counts`，乘 `0.000244` 约为 `1.004～1.040g`，
  乘旧系数则约为 `0.502～0.520g`。这是加速度系数的独立旁证；归一化后的方向比较不能验证加速度倍率。
- 每节点主机接收节奏约为 `104 Hz`，不等于已取得设备时间戳或确认设备同步。

相对历史配置文件，陀螺系数是四倍、加速度系数是两倍；不能仅凭“量程翻倍”推出这两个系数，
也不能直接将解算角度乘二。配置中的验证标志保持未验证。

新手套另显式设置 `vqf.biasClip = 8.0`（°/s），使用 VQF 官方的最大预期陀螺零偏参数。
2026-10-24 录制的低运动片段中，12 路陀螺 Y 轴的恒定分量约为 −2.71～−3.95°/s，
超过默认的 2°/s。默认值既限制偏置估计，也会阻止这类输入进入静止校正；同段原始数据重放已验证此影响。
这个参数不改变单位换算、不直接减固定偏置，也不修改手指角度或标定阈值；在线与离线回放使用同一设置。
旧配置未声明 `vqf` 时继续使用官方默认值。增大偏置范围也会扩大可被视为静止的恒定角速度范围；
六轴输入仍无法独立区分绕重力轴的慢转与偏置。不能把短时稳定性改善当作手型精度或长期无漂移验收。

先结束占用同一串口的旧会话，再用独立环境从仓库根目录启动：

```bash
env -u PYTHONPATH OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  /path/to/fsglove-venv/bin/python -I -m vt_fsglove12 upstream-live \
  --fsglove-source /path/to/pinned/fsglove-source \

```

此命令只预填串口，连接由操作者点击。命令不覆盖新配置的输出频率。
以后在主界面启用新配置时，须同时检查配置文件路径和“输出频率”：工作站中的 `30 Hz`
参数会通过命令行覆盖 JSON 内的 `104 Hz`。清空“输出频率”可继承 JSON 的值，避免两处配置失配。
目标输出频率、每路输入频率、有效手势输出和界面刷新
是不同指标；未标定时诊断 JSONL 默认约每秒记录一次，不能据此判断原始输入只有 1 Hz。

编号或单位改变后重新标定，不修改旧 profile 摘要来复用旧结果；已有录制和标定保持原样。
实机验收按以下顺序记录原始数据和结果：

1. 明确确认手套各部位静止后采样，检查加速度模长、陀螺零偏和姿态随时间的变化。
2. 做已知起止角度的受控倾转，选择能改变重力方向的转轴，比较积分角度与实际转角；仅绕重力轴转动
   无法用加速度方向验证角度。
3. 重新完成三步标定，再检查单指、全手动作及回到初始姿态后的对应关系。

采集中，手模上方固定显示当前动作和倒计时。全手校准先采集伸直静止参考，再提示四指弯伸；
应按当前阶段操作，按钮点击后立即弯曲会把运动混入静止参考。

上述验收尚未完成，不能把自动化测试或低运动录制当作已确认静止的实测。编号置换与物理单位等价测试
不证明实际安装轴向、设备同步、静止漂移或手型精度；试用主程序新配置后仍须完成这些验收。

### 高频姿态解算（120 Hz 目标）

在正常 `upstream-live` 命令末尾增加 `--output-rate-hz 120`。它只覆盖**新会话**的目标频率，
不改磁盘上的配置、不热改当前窗口、不自动连接串口。目标不能超过配置中的 `sample_rate_hz`。
CPU 小矩阵路径推荐启动前设置 `OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1`。
先按安装章节准备单独的 Python 3.12 环境，再从仓库根目录安装已测高频依赖。
将示例环境、源码、模型目录与串口改为实际值；如有旧窗口，请先正常结束会话：

```bash
/path/to/fsglove-venv/bin/python -m pip install \
  -r tools/fsglove12/requirements-high-rate-tested.txt
env -u PYTHONPATH OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  /path/to/fsglove-venv/bin/python -m vt_fsglove12 upstream-live \
  --fsglove-source /path/to/authorized/fsglove-source \
  --mano-assets /path/to/authorized/mano-assets \
  --output-root tools/fsglove12/output/upstream_live \
  --port /dev/ttyACM0 --output-rate-hz 120
```

串口路径以本机枚举为准；ROS 联合启动则增加 `output_rate_hz:=120`，见[桥接说明](../../ros2_ws/src/vt_glove_bridge/README.md)。
新连接的滤波状态与会话绑定变化，仍需正常完成标定；不能手改旧 profile 摘要绕过绑定。

ROS 联合启动的 `glove_python` 也须指向这个环境；只调整频率不会自动切换依赖。
高频依赖清单采用对照验证过的 SciPy 1.16.3，原开发环境的对照版本为 1.18.1；
这种选择用于减少参考环境中小矩阵旋转运算的调度开销，不是通用的“版本越旧越快”结论。

本轮性能优化保留现有 FSGlove/QMT 数学方法和逐关节有效性判断：

- 每帧调用一次原始官方 anatomical FK，再使用原始 manotorch composer 得到 MANO 表示；
  保持原来的 dtype、转换顺序及根姿态覆盖，不改 pinned 源文件。`adapter_execution` 记录适配层的执行方式。
- 缓存固定安装旋转和逆变换；校准对象或其内容变化时失效。QMT 投影只在**同一帧**复用，
  旧/新航向参数使用 QMT 自带批处理，不从上一帧借用角度，不增加运动平滑。
- 官方 GUI 路径目标频率大于 30 Hz 时，姿态和传感器朝向 JSONL 的编码、写盘自动交给
  **独立记录进程**，减少与解算线程竞争 Python 执行时间；30 Hz 和直接使用 `LiveController`
  的默认路径保留后台线程。原始串口记录方式和 ROS 消息结构不变。
  记录入口为有界队列，正常退出时排空并关闭；容量耗尽、序列化或磁盘失败明确记录，
  按记录失败策略结束会话，不静默声称数据完整。`summary.json` / runtime 的 `result_recording`
  提供接收、写入、刷新及未完成计数；`flushed_pairs` 不是断电后持久化的保证。
- GUI 最新值传输最高 60 Hz，ROS 从解算线程直接发送，不受 GUI 定时器限频。
  实时表面网格使用只读 NumPy 数组和缓存拓扑，减少数千个 Python 列表的逐帧复制与垃圾回收；
  可视化形状不变，公开离线 `ManoBackend` 默认仍返回 JSON 兼容列表。
  为保留 21 关节点语义，当前每次解算仍运行真实 MANO；不把上一帧网格配到新姿态上。
- 计算进程内部发布 GUI 快照时，对只替换、不原地修改的结果直接同步序列化，避免先深拷贝
  整个网格；公开快照接口和 GUI 收到的对象仍独立，不能反向修改解算状态。
  缩短状态锁持有时间，移除内置融合器和输入快照路径上的重复复制；不增加时间平滑或预测帧。

源身份使用滤波 epoch 和样本计数；修改时间戳不构成新输入。重复输入不重复计算有效姿态，
标定变化后的同源重算和不可用状态不计入“新输入解算频率”。ROS `metadata_json.source_fresh`
标识源输入是否更新，`source_sample_indices` 和 `source_filter_epochs` 仍是核对依据。
新输入也不等于每个关节有效，仍须检查 `pose_valid` 和逐关节质量。

窗口分别显示新输入解算 Hz、目标 Hz、完整处理周期及超期计数；画面刷新 Hz 另列。
120 Hz 的周期预算是 **8.33 ms**。应在真实串口、GUI、ROS 和录包一起运行时验证，
不能用重复旧值、插值、`ros2 topic hz` 单一统计或离线吞吐代替验收。

新增发布路径的线程/进程记录及 GC 对照运行中，完整朝向/姿态结果的规范化摘要一致：
只排除四个明确列出的性能计时字段，不对数值取整，也不排除质量、状态或源身份字段。

快照获取加实际编码的中位开销约 0.25 ms，旧快照深复制本身约 1.10 ms；两者统计范围不同，
新版计时还包含编码，不能把它们说成完全相同的微基准。
加入 `--trace-gc` 可记录被动 GC 事件及其与慢帧的时间重叠，不关闭自动垃圾回收。
单独的跟踪运行确认一次约 79 ms 的第 2 代垃圾回收与约 86 ms 的慢帧完整重叠，
但其他慢帧并非都有 GC 事件，不能把所有延迟归因于 GC。

启动阶段 `gc.freeze()` 仅保留为**默认关闭的实验**：相同初始化顺序下没有稳定改善整段最大延迟，
不作为交付版的性能保证。基准开关为 `--startup-gc-freeze`；官方高频 GUI 的实验开关为
`VT_FSGLOVE_STARTUP_GC_FREEZE=1`，只作用于新计算子进程加载模型后、创建采集会话前的边界。
它冻结边界处所有已跟踪对象，并非只冻结模型；自动 GC 继续运行，涉及冻结对象的循环引用
可能延迟到关闭时解除冻结后才能回收。正常使用无需设置该变量。
有关冻结语义见 [Python 3.12 GC 文档](https://docs.python.org/3.12/library/gc.html#gc.freeze)。

本轮回归：手套模块 **1304 项通过、3 项跳过**；ROS 桥接 **108 项通过**，包含合成数据 DDS
回环测试，不是硬件频率验收。模型资源相关测试使用了本机真实资源；短窗口中未出现 GC
长停顿的个别运行，也不能证明长时间运行不会再出现。

**当前结论：高频路径已实现，尚未证明真实硬件全链路稳定 120 Hz。** 这些记录原本不是
120 Hz 的已解算轨迹，基准没有插值、补帧或修改源时间。完整计时仍不含实际串口/VQF、
Qt 绘制和 ROS DDS；单次平均吞吐超过 120 不能替代长时间逐帧时限验收。
本次旧录制基准在原 Python 环境中隔离加载 SciPy 1.16.3，没有改写旧 profile 的依赖绑定；
新建优化环境中依赖绝对路径发生变化，因此旧 profile 仍会按原规则拒绝，须新会话正常标定。
数值对照脚本为 `scripts/compare_pose_environments.py`，使用 `--help` 查看两个 Python
环境及冻结窗口参数；报告保留输入摘要和依赖版本，不凭性能结果宣称姿态更准确。

### 输入单位修正与近轨提示

2026-10-01 的原始数据复核发现，旧默认配置给拇指节点 **5/6** 使用的 `0.0175 dps/LSB` 二倍覆盖与两组三姿势的重力方向变化、真实 VQF 回放不一致。新版 [right_current.json](src/vt_fsglove12/configs/right_current.json) 与候选三拇指布局均移除该覆盖，5/6 继承全局 **`0.00875 dps/LSB`**；其他节点不因这次修复自动更改单位。`units_verified=false`、`sample_rate_verified=false` 仍保留：这是这套录制硬件上的经验一致性验证，**不是读取固件量程寄存器后的确认，也不能直接套到任意另一副手套**。

通过生产 `OnlineFusion` 对同一真实原始窗口的 **209,562 条样本**做有界回放，两段相隔约 5 秒的低运动窗口之间，节点 5 的 VQF 姿态变化由约 **26.65° 降为 0.68°**，节点 6 由约 **26.50° 降为 0.78°**；原始加速度方向变化分别约 **0.43° / 0.45°**。两分支使用相同原始样本与名义周期，只显式改变 5/6 的单位转换，没有增加时间平滑、丢弃样本或强行归零。滤波器从该回放窗口起点重新初始化，**这些数值不是关节角误差、已知静止真值或“全手已无漂移”的证据**；近编码边界事件也不能单独证明发生了物理饱和。

让修正用于下一次现场测试：

1. 正常断开并结束旧窗口，保留旧会话数据；新版不会热改正在运行的滤波状态，也不会自动关闭旧程序。
2. 用新版默认配置启动并手动连接。若仍传入自定义 `--config`，检查其中 5/6 的覆盖值；程序不会替你修改旧文件。
3. 在新会话重新完成**官方三姿势**，再按需要做全手/单指功能标定。输入换算与滤波轨迹已变，旧安装与功能 profile **不能直接复用**；配置、会话和 epoch 绑定不能通过手改摘要绕过。
4. 先做舒适、缓慢的弯伸和回位，每次完整弯伸约 3–4 秒；再保持指形、缓慢转掌。若出现编码边界提示，打开下述逐路输入详情对照原始整数和配置；不能仅凭提示要求操作者反复重标定、认定硬件故障或增大量程。

新增输入质量提示读取陀螺 **原始整数**：任一轴绝对值达到 `32760` 时记为接近 int16 编码边界。`orientation.sensor_quality.gyro_near_rail` 保存阈值、每节点累计样本/近轨数、近 2 秒计数、相关轴和最近时间；`active_nodes` 表示近期仍有提示的节点。累计计数不会因两秒后恢复就清零；若近期事件过多，`recent_counts_complete=false` 表示近期细项已达到有界记录容量，不能当精确近期总数，累计计数仍保留。

**编码边界事件不等于物理饱和，也不是手模型的软件关节限位。** 2026-10-03 起，界面不再将它直接称为“疑似截顶”，不宣称没有事件就一定没有饱和。保留兼容字段 `gyro_near_rail` / `node_N_gyro_near_rail`，其 `interpretation` 为 `encoding_boundary_event_not_physical_saturation`，`physical_saturation` 为 `unknown`。一条事件即可显示近两秒提示，不代表连续两秒的平台。编码边界监测本身不阻断采集、不筛除标定样本、不修改原始数据、不改变滤波状态或 epoch，不向设备发送命令；下述可选解算输入保护是独立处理，启用后会改变送入 VQF 的异常输入。物理饱和必须结合明确的固件字段语义及配置验证；确认改变输入单位后，才应使用新配置、新会话和匹配的标定。

### 解算输入保护：当前右手配置启用，旧配置保持兼容

当前随包的 `right_current.json` 及本机运行配置均显式启用保护。本机启动脚本通过 `.runtime/env.sh` 的 `VT_GLOVE_CONFIG` 选择配置，不能把旧录制的经验量程覆盖当作当前硬件配置。历史配置缺少 `input_filter` 时保持关闭，确保旧录制仍能按原配置复现；不会擅自给旧配置开启。其他配置可在新会话使用的 `--config` JSON 顶层加入以下字段；设为 `false` 可显式关闭。启动后按正常流程完成本次会话标定，不会热改已打开的窗口：

```json
"input_filter": {"enabled": true}
```

保护位于原始量换算后、VQF 输入前。2026-10-05 的 `per_axis_gyro_continuity_v2` 修正了两项会人为丢失转角的问题：某个陀螺分量异常不再替换另外两个正常分量；连续的编码边界报告值不再被一律当成零角速度。陀螺按 X/Y/Z 分别维护因果突变确认，正常分量原值直通；非有限值和孤立突变仍拦截，加速度仍按完整向量做原有有效性检查。

编码边界只说明报告值接近整数端点，不足以证明其无效。平滑抵达边界时继续积分报告值；突然跳到边界时，第一样本进入突变确认，下一条一致的有限值才能通过。首次输入就是边界值且尚无基线时也须确认。**保留报告值不等于证明没有物理饱和，更不能重建未被报告的超量程转角。** 这不是关闭过滤，也不会放行从正常静止值突然出现的单点边界尖峰。

处理只使用当前及过去样本，不对全部运动做连续平滑。名义 120 Hz 下持续阶跃的确认通常增加一条样本、约 **8.3 ms**，不是整条显示链路的延迟保证。被拒绝的陀螺分量最多保持两条采样周期，持续不一致或非有限时仅该分量改用偏置回退；其他分量继续更新。异常加速度跳过本次加速度更新，不阻断其他节点。

短突发不因保护动作而重置滤波 epoch，也不额外要求重做标定；连续拒绝超过 **0.25 秒**时相关姿态会降级为不可用，不能把保持的数值当作仍被观测到的运动。被拦截期间的真实转动无法从缺失输入恢复：画面稳定不等于姿态正确，此功能也不能修复错误单位、动态佩戴滑移或六轴航向漂移。

启用时主界面以**处理结果**为准：短时异常已处理时显示“异常输入已拦截”，相关通道为蓝色，不再把已处理的原始边界值显示为橙色故障；边界值按连续性规则通过时明确说明已积分报告值、是否饱和未确认，不再误称未处理。累计拦截数是历史统计，不代表当前故障。持续异常导致姿态不可用、或缺少可核对的处理状态时，仍显示需要关注的提示。保护关闭时保留原始边界提示，不伪装成已过滤。

“12 路输入配置 / 实时值”保留同帧原始数值、边界事件的原值/时间/样本号，以及“解算输入保护”列中的具体动作；主窗口与详情的快照编号一致，但前者说明处理结果，后者保留诊断证据。累计数按样本计，同一条六轴数据的陀螺和加速度同时异常不重复计数。**`raw.csv` 和快照 `raw_values` 始终保留原始整数，不平滑、不截断、不改写**。`gyro_rad_s` / `accel_m_s2` 仍是原始整数换算后的物理量；保护状态记录在 `input_filter`，真正送入 VQF 的值另存 `fusion_gyro_rad_s` / `fusion_accel_m_s2`，仅保留在姿态日志、不加入 ROS 出口。不能用保护后的解算输入替代原始证据。

回放旧录制应显式传入原会话保存的 `--config`；要验证保护的影响，请复制配置并显式启用保护、输出到新目录，保留源 `raw.csv`、旧配置和原结果，不能把新结果称作原算法复现。

`input_filter.revision` 固化本次处理规则；逐节点还保存 `gyro_action_by_axis`、`gyro_rejected_axes`、
`gyro_boundary_integrated_axes` 及按轴累计的边界、保持、偏置回退次数。这些诊断随结果进入 ROS `quality_json`，
不含原始 IMU 数值。恢复正常输入不会抹掉历史替代计数；当前 `orientation_valid` 仅表示当前输入处理可用，
不保证此前缺失的转角已恢复，也不是人体姿态准确性认证。新代码不会热修已经积累错误的 VQF 状态或旧 profile；
下一次正常启动建立新会话。旧记录有保护配置时，若要精确复现旧行为，还必须使用对应旧代码版本，不能只凭相同配置认定算法相同。

### 高频稳定性：接收完整性保护与完整标定窗口

`input_health` 是独立于上述 `input_filter` 的接收完整性保护；高频优化没有取消原有异常过滤。
新版 `right_current.json` 和本机当前运行配置均显式启用
`"input_health": {"enabled": true}`。历史配置缺少该字段时保持原行为；旧窗口不热更新，
须在测试完成、正常结束旧会话后的新窗口中生效，不自动重启或连接设备。

默认先用约 **2 秒**逐节点聚合接收计数确认节奏，USB 同时间戳批次照常计数；接收率持续约
**1 秒**低于名义值的 0.5 倍或高于 1.5 倍才确认速率故障。冻结 bank（1–6 或 7–12）须有
六路完整六轴值及 status 重复至少 12 次、持续至少 1 秒，同时另一 bank 至少变化 6 次，
且重复 bank 至少两路陀螺达到 5 dps；静止重复读数本身不构成冻结结论。这些是软件输入证据，
不是芯片 ODR、物理饱和或硬件故障诊断。**不将主机包间隔替换为 VQF 积分周期，不自动改量程、
采样率或发送设备命令。** 初始确认期姿态暂不可用，但尚未因故障暂停积分。

确认故障后，受影响通道暂停 VQF 更新，原始记录、接收计数和异常过滤诊断继续保留；暂停时
`fusion_gyro_rad_s` / `fusion_accel_m_s2` 为 `null`，表示没有本次积分输入。每次故障只失效一次
对应滤波 epoch，不逐帧重置；清除标定不能洗掉故障。恢复须有持续至少 1 秒健康节奏和每路至少
12 次真实 payload 变化，然后重建滤波器；旧 profile 不会自动恢复有效，须在输入健康后重新标定。
**先恢复设备输入，不要在冻结或约 6 Hz 的流上反复标定；已丢失的真实运动无法从重复值补回。**

30/120 Hz 解算现在都按完整采集时段分桶：2 秒静止段最多 120 帧、8 秒功能动作段最多 300 帧，
保留各时间桶内最新真实快照，不再达到帧数上限后只使用前半段。开始、采集中和保存前均检查输入
健康，异常采集不保存新 profile。短暂 root 缺测不再直接清空功能铰链参考，恢复仍受源身份、
间隔和 epoch 检查约束；真正输入故障或参考变更仍会失效。

界面以稳定文字区分“正在确认接收节奏”和“冻结／速率异常／恢复中”；完整手形可保持显示，
但保持画面不是新测量。输入不健康时，ROS `pose_valid=false`、`metadata_json.source_fresh=false`，
`reason=input_health_invalid`；`quality_json.input_health` 只发布健康摘要，不带原始六轴值或 status。

### 本地日志容量与故障隔离

本地文件记录与实时串口读取、姿态解算、界面和 ROS 结果发布相互独立：磁盘空间不足、
写入失败或达到本地容量限额时，停止本会话的本地记录，不因此关闭串口或停止解算、ROS 发布。
界面持续显示“本地记录已暂停”及原因；该提示不改变 IMU 健康颜色，也不会被普通状态消息覆盖。
暂停后的数据**没有写入本地文件**，不能把继续显示的手形当作仍在成功录制。

- 未标定或不可用结果的重复诊断默认记录约 **1 Hz**，状态变化额外记录最多 **5 次/秒**；
  新鲜、有效的解算结果不因这项日志节流降低记录频率，也不改变算法或 ROS 输出频率。
- 默认当前会话原始 / 调试日志达到 **2 GiB**，或记录磁盘剩余空间低于 **2 GiB** 时，暂停这些连续日志。
  已被写入队列接收的数据允许有限收尾，因此这是容量保护，不是精确到字节的文件截断。
- 容量限额或 I/O 故障结束的会话标记为 **incomplete**，保留接收量与实际记录量及错误信息。
  若磁盘已无法写入，结束摘要本身也可能保存失败；以界面持久警告和实际文件为准，不能承诺摘要总能落盘。
- 不自动删除历史文件，不在原会话中自动恢复连续日志；处理空间问题后，由用户显式重新连接创建新会话。
- 小型标定文件与触指任务独立保存，**不受上述 2 GiB 日志阈值阻断**，但仍可能因实际空间不足、权限或 I/O 错误失败。
  保存失败保留本次内存结果，明确显示“待保存”；处理故障后点击“重试保存标定”，或点“另选保存目录”保存待保存的标定文件和触指任务，
  不需为了重试保存而重新连接或重新采集。只有保存成功才标记为“已保存”。
  另选目录后，本会话后续标定文件也使用该位置；连续日志的位置和暂停状态不变。
  单份小型标定文件上限为 16 MiB，写入时保留至少 16 MiB 磁盘余量；这不是无限写入或取消磁盘保护。
  待保存缓存有界，关闭程序仍会丢失尚未落盘的数据；请先确认“已保存”，再退出或清除标定。

上述策略只管理本工具的本地日志。**外部 `ros2 bag record` 独立运行、独立占用空间，
不受本工具的 2 GiB 会话限额约束**；本地记录暂停不等于 bag 已停止或完整，需分别检查。

```bash
vt-fsglove12 inspect-input \
  --raw /录制会话/raw.csv \
  --config /录制会话/config.json \
  --max-samples 100000 \
  --output /已有报告目录/input_report.json
```

`--max-samples` 统计各节点合计的前 N 条记录，不是每路 N 条；仍在写入的文件建议使用有界前缀。报告保存实际读取的完整行字节数与 SHA-256、每路样本数、原始极值、六轴编码边界次数、连续边界样本数、接收间隔及名义周期对照。缺测节点仍列出，频率为 `null`；不足一秒或全部在同一主机时间戳时不虚构 Hz。重复值不自动去重，因为静止时重复也可能合法。运动期间的加速度模长均值不能当作重力标定。

**漂移不能只靠改告警解决，也不能全部归因于六轴航向不可观测。** 换算系数不匹配会让陀螺积分与重力方向不一致，出现停手后仍缓慢回正；这是输入层错误，应先纠正。下方工具可从已标注动作独立验证逐路有效换算系数，不需要等待固件源码。它不能代替 STM32 的字段定义、各节点 FS/ODR 与发包策略，也不把拟合结果称为寄存器读回。输入正确后，六轴 VQF 仍未观测绝对航向；三姿势标定也不保证长期相对航向无漂移。

参数或输入契约变化只用于新会话，不热替换运行中的 VQF；旧录制和旧配置不改写。新默认配置增加型号声明后摘要会变化，不应手工改旧 profile 的摘要强行复用。

历史数据应区分两种用途：

- **复现原记录**：显式传入原会话保存的 `--config /原会话/config.json`，沿用当时单位、名义周期及间隔策略。新默认值不会自动识别历史文件，不能省略配置后把新结果称为原算法复现。
- **显式纠正验证**：复制原配置到新的分析目录，只修改已声明的候选参数，原始 CSV、原配置和旧 profile 保持不动；输出写入新目录并标明原值、新值和窗口。不要将该结果冒充原会话在线姿态，也不能把旧 profile 直接套到新的融合输出。

没有原采集配置时，应先说明参数来源与不确定性，不凭文件名猜单位。六轴相对航向漂移、佩戴滑移、缺测关节先验与人体精度问题仍然存在；本次输入修正不是在线相对 yaw 校正。

### 已有录制：逐路校验并生成修正配置

`fit-input-units` 用**静止端点的加速度方向**检验中间陀螺积分，不把 VQF 自己的输出当真值。先用一个合格转场选择候选，再用其他独立转场复核；只对证据足够的节点生成 `0.5×` 或 `2×` 换算建议，正常节点保留原值，证据不足的节点单独列出，不中止其他节点。原始 CSV 不裁剪、不平滑、不改写。

```bash
vt-fsglove12 fit-input-units \
  --raw /原会话/raw.csv \
  --config /原会话/config.json \
  --events /原会话/events.jsonl \
  --bias-window /已标注的静止偏置窗口.json \
  --report /已有分析目录/input_units_report.json \
  --output-config /已有分析目录/corrected_config.json
```

`--events` 只选已完成的官方三姿势采集：准备 3 秒、保持 2 秒，取保持阶段中心 0.5 秒；原始数据还须通过静止一致性检查。替换、取消或未完成的采集不算有效窗口。也可用互斥的 `--windows` 指定 JSON 数组，每项含 `start_s`、`end_s`、`label`；至少三个有序、不重叠窗口，形成训练和独立验证转场。

窗口默认以录制第一条原始数据为时间零点；绝对主机单调时间需显式写 `"time_basis": "absolute_monotonic"`。例如**确实知道录制最初两秒静止**时，偏置窗口文件可以是：

```json
{"start_s": 0.0, "end_s": 2.0, "label": "confirmed_initial_rest"}
```

不要把缓慢转动当成陀螺零偏；这会让校验本身出错。`--bias-window` 可省略，但只有端点足够静止时才允许估计偏置，否则报告证据不足，不硬套一个比例。程序保留窗口、原始前缀 SHA-256、逐路残差、候选与复核结果。输出文件须不存在；候选配置通过 `--config /已有分析目录/corrected_config.json` 用于新的回放或窗口。

**更改换算系数后，必须由新融合输出重新拟合安装/功能标定，不能沿用旧 profile 或手改摘要。** 历史回放可以用原始数据和原标注重新拟合，无须重复采集。实时程序不会热替换运行中的 VQF，也不写设备。拟合的是给定采样周期下的有效陀螺换算，不能单独区分固件缩放、传感器量程与设备采样周期；加速度量程和绝对航向也不由此得到认证。

2026-10-02 的已标注会话中，独立动作支持仅对 5/6/7/10 号使用原陀螺系数的两倍，其余八路保留原值。这不适用于所有历史会话，也不自动成为所有设备的默认值；不能仅凭 IMU 型号或同一块采集板，假定 12 路参数始终相同。

### 无尺子流程：三姿态自动检查输入尺度

官方 `upstream-live` 窗口及 ROS 联合启动的同一窗口，现在包含
**“三姿态输入尺度检查”**。这里检查的是原始 IMU 的有效陀螺换算，不是手长、指长或 MANO 手形尺寸。
无需量尺，也无需输入已知精确转角；仍需按指引完成有充分倾转的动作。
首次使用更新后的代码需要重新打开程序；不会热更新已运行的窗口。

操作顺序：

1. 手动连接，按照[官方三姿势](#官方三姿势水平--指尖朝上--指尖朝下)完成水平、指尖上倾、指尖下倾。
   五指保持伸直，每步准备 3 秒、静止 2 秒；动作间尽量在 20 秒内衔接。只绕竖直方向左右转手不能完成此检查。
2. 三步结束后自动后台检查。在每个 2 秒保持段内，以 0.05 秒间隔寻找 0.5 秒静止子段：先选合格通道最多的窗口，再比较静止噪声。
   选窗不使用融合四元数或拟合残差。随后复用 `fit-input-units`，第一段倾转拟合、第二段独立复核。
   即使安装标定拟合失败，只要三段采集完成且有原始数据，仍可得到输入尺度检查结果。
3. 查看面板或点击“查看逐路结果”。检查本身不改变当前参数、不暂停采集，也不是新增的全手通过门禁。

| 每路结果 | 含义及下一步 |
|---|---|
| 当前尺度受支持 | 本次倾转和留出段支持当前系数；继续功能轴标定，不需更改该路 |
| 建议调整 | `0.5×` 或 `2×` 候选同时通过拟合及独立复核；界面列出节点和候选系数 |
| 证据不足 | 保留当前系数；详情区分未静止、缺样、倾转不足、时序不相容等原因，不称为硬件损坏 |

有建议时，可点击 **“采用候选并断开（重新连接标定）”**：程序正常关闭当前会话后，
为下次连接使用候选系数，并创建无旧标定缓存的官方后端。不会自动重连，也不会把新系数塞入正在运行的滤波器。
再点击“连接”，重新完成三姿态及全手功能轴标定；主界面和 12 路输入子窗口显示同一份新换算配置。
没有证据的通道不修改。原配置文件、旧 raw/profile 不覆盖；旧 profile 不能用于新尺度。

每次检查在当前会话下创建独立的 `input_scale_<唯一编号>/`：

- `raw.csv`：本次有限缓存的原始样本副本，保留接收顺序、原值与状态字；不是滤波输出。
- `report.json`：选窗、逐路结论、拟合/留出残差、配置及原始数据哈希绑定。
- `config.candidate.json`：仅有通过复核的调整建议时生成。可通过“打开报告目录”找到。

采用只影响本次打开的程序后续连接。下次重新启动程序时，如需继续使用已审阅候选，
在原 `upstream-live` 启动命令中指定 `--config /实际路径/config.candidate.json`，其余参数不变；
ROS 联合启动对应 `config:=/实际路径/config.candidate.json`。
不自动改写启动脚本或系统默认配置。重新连接仍需标定。

技术边界：原始缓存从本轮三姿态开始，最多保留 90 秒/180,000 条单节点样本；每段转场最长 30 秒。
等待过久或缓存不完整会给出证据不足，此时可连续重采三步，既有姿态记录不会删除。
重采、清除或断开会使旧检查结果失效，迟到结果不会重新激活旧候选；同一时刻只运行一个检查作业。
数值检查在独立进程运行，启动与大对象传输也不在实时解算线程执行，但仍需真机验证整机负载下的时延。

这验证的是**配置名义积分周期下的有效增益**，不能独立区分所有尺度与采样周期错误，
不能读回芯片 FS/ODR，也不验证绝对航向或人体精度。此功能不解决个人手形、拇指 CMC/MCP 分解或触指接触间隙；
后续仍需做整掌转动保持指形、重复弯伸回零和触指验证。它不是“全手标定已完成”或“已保证无漂移”。

### 统一连续铰链估计 v3 与逐关节质量（功能轴启用时应用）

**重新标定无需退出窗口：** 点击“清除本次标定 / 重新开始”，会取消正在进行的采集、清除三步标定及所有手指功能参数，并重置各 IMU 的 VQF、输入保护参考、航向与角度连续性缓存。串口和原始记录保持连接，已接收节点的滤波 epoch 递增；清除完成后直接从第 1 步重新采集。清除期间旧手形、成功标记和历史结果不再显示为当前有效结果；按钮在普通采集及全手计算期间也可用于中断重来。历史 `profile.vNNN.json`、原始数据及累计故障计数保留用于追溯，它们不是清除后仍在生效的标定参数。事件日志记录 `clear_generation` 和新的滤波 epoch。首次升级到支持此功能的代码需要重新打开窗口一次，之后每次清除不需要重启或重新插拔。

此前“小指专用航向修正 → 功能轴投影 → 独立角度连续性”的叠加路径已由 `FunctionalPosePipeline` 统一管理。四指 PIP（MANO slot `2/5/8/11`）与拇指 IP（slot `15`）共用 `FunctionalHingeEstimator`：同一状态拥有已接受的相对航向、当前四元数投影、±2π 角度分支及质量。已标定的小指不再因为残差跨过门限而切回未校正的裸投影；其他已标定铰链遵循相同规则。四指 MCP 仍保留侧摆和弯曲两个自由度；掌根、拇指 MCP/CMC 及未启用功能条目的关节不被套用单轴铰链约束。

估计器继续真实调用 QMT `estimateDelta1d` / `1d_corr` 与 `quatProject`，但**不再用单帧理想铰链假设重新估计航向**。启动时增量航向为零，使用已绑定的安装与功能中立参考；这不是声称测得了绝对航向，也不会在第一帧强行消掉任意漂移。

当前姿态与参数估计分开：

- 当前新鲜四元数逐帧做 QMT 投影，不等待窗口、不对屈伸做低通或角度幅度缩放。
- 航向候选使用过去最多 4 秒、最多 10 Hz 的真实新鲜样本，最小跨度 2.5 秒，最多每秒拟合一次。要求局部屈伸、父骨段倾角都有充分变化，前后半窗及不同倾角分组的候选一致。纯整掌转动、纯世界 yaw 旋转或静止都不能单独证明模型可靠。
- 候选不能仅通过“降低理想单轴残差”而被接受；若它将原本固定的偏轴误差变成随掌姿变化的残差，则拒绝该候选。QMT 几何 `rating ≥ 0.2` 和偏轴残差 `15°` 不再单独充当航向可信证据。
- 航向参数渐进、限速应用；判断最近手指运动时，用**同一个参考**重投影历史样本，避免参数修正自身被误认作运动而形成停手后继续追参数的反馈。保护、缺失或不同步的输入会中断拟合窗口，不能把坏片段拼接成新证据。
- 没有充分证据或证据超过 10 秒时，保留已接受的参数，继续计算当前投影，标记 `degraded`；**不因为航向缺少激励就清零、冻结角度或宣称串口断流**。新的窗口证据、参数收敛及当前残差满足条件才标记 `valid`。证据时限不是漂移误差的上界。

真正输入过期、依赖不满足、滤波 epoch 不匹配、非法四元数或投影不唯一仍为 `unavailable`；会话、安装/功能参考与源时间不连续按绑定规则重置。暂估角是真实当前输入的投影，不是历史显示缓存，消费者必须查看质量。

上述窗口与一致性阈值是工程初值，不是人体精度指标。本改动针对已观测 PIP/IP 的“偏轴误差被误作航向漂移”路径，**不代表已消除手掌与近节差分参考误差造成的所有 MCP 耦合**，也不解决拇指 CMC/MCP 分解或真实触指精度。个人手形由下文独立的触指标定流程处理；功能轴校正本身不拟合手形，也不能替代人体动作验收。

### 官方三姿势：水平 → 指尖朝上 → 指尖朝下

三步始终保持五指自然伸直，转动整只手掌。每步点击采集后，准备 3 秒，随后静止采集 2 秒。**后两步绕同一转轴，不能套用 legacy 的“指尖下倾 + 拇指侧上抬”两个不同转轴动作。**

| 顺序 | 官方名称 / 数据键 | 动作 |
|---|---|---|
| 1 | `HORIZONTAL` / `base_pose` | 手掌水平、掌心朝下，五指伸直，保持不动 |
| 2 | `VERTICAL_UP` / `z_rot_pose_1` | 指形不变，使整掌指尖向上倾约 50°，保持不动，不要同时侧翻 |
| 3 | `VERTICAL_DOWN` / `z_rot_pose_2` | 沿同一转轴，使整掌指尖向下倾约 50°，保持不动，不是拇指侧上抬 |

`VERTICAL_UP/DOWN` 是官方状态名。界面上倾/下倾约 50° 的示意对应同轴相反方向；[固定版本官方说明](https://github.com/davidliyutong/fsglove/blob/a7988f051c35f5ee6157353ee4022d73aa1e4cc8/src/hand_visualiser/README.md#calibration-pose)建议两姿态总转角至少 90°。不要求精准竖直，也不要追求两姿态恰好相差 180°，以免出现转轴符号歧义。只在舒适范围内转掌，不要勉强到疼痛；这仍是硬件引导适配，不是论文实验协议已通过复现。

三步采齐后调用官方安装标定与推理。新增 `calibration_motion_diagnostics` 记录各实测槽位相对平掌的转角、上下反向同轴偏差、总转角及转轴偏离水平的程度。掌部偏轴、幅度过小或总角不足时，界面显示软提示并保留结果，不因此硬停或要求重连；可保持五指伸直、避免同时侧翻，单独重采第 2/3 步。数值退化、无有效手掌或会话不匹配等原有错误检查仍然有效。**这些是采集一致性提示，不是人体角度精度指标，也不证明侧偏或持续漂移已消除。**

不能用当前人的动作改变旧 CSV，也不能把没有这些姿态的历史录制标成已完成官方标定。官方模式不执行旧 hand-eye 拟合、`SparseHandSolver`、legacy 功能轴流程或旧“仅重设伸直参考”；legacy 算法的 profile 不能混用或失败后静默回退。下述可选功能轴适配与 v2 缺测 DIP 联动是独立的外围处理，不是 FSGlove 官方新增算法。

### 原始 16 路核心与当前缺测适配的边界

官方 `Raw2MANOCalibrator` 接受 16 个绝对 IMU 旋转。当前默认布局实际是 **12 路采集、11 个骨段映射**，11 号辅助通道不映射；槽位 `3/6/9/12`（四指远节）和 `13`（拇指 CMC 所在骨段）缺测。

新建官方 profile 使用 `official_fsglove_raw2mano_with_explicit_sparse_adapter_v2`。对**缺测的四指 DIP**，默认以当前帧 PIP 的正向弯曲角联动：`DIP_z = min(1.65, 0.65 × max(0, PIP_z))`，角度单位为弧度，DIP 的扭转/侧摆先验保持零。它只在该指近节与中节两个骨段当前均有有效观测时应用；任一依赖缺失、过期或 epoch 不匹配，缺测 DIP 回退中立零位，不沿用上一帧。拇指 CMC 和其他缺测槽位仍保持中立先验。

适配器按官方公式反解这些目标先验所需的虚拟 IMU 输入，再交由**未改写的官方核心**输出 MANO 姿态；不是复制相邻 IMU、替换求解器或事后改网格。实测槽位输入始终保持不变，包括实测 DIP；完整 16 路输入不做缺测补全。缺测标定槽位使用明确标注的合成参考，其坐标选择在反解中抵消。

可在 `--config` 指定的布局 JSON 中调整外围先验；新配置应重新生成匹配的 profile：

| 配置键 | 默认值 / 含义 |
|---|---|
| `dip_ratio` | `0.65`；所有四指的基础联动比例，范围 `[0,1]` |
| `dip_ratio_by_finger` | `{}`；按 `index`、`middle`、`ring`、`little` 单独覆盖比例，范围 `[0,1]` |
| `upstream_dip_max_rad` | `1.65`；缺测 DIP 弯曲先验上限，必须为 `(0,π)` 内的有限弧度值，不是实测角的限位 |
| `upstream_missing_slot_policy` | `pip_coupled_dip_with_neutral_other_missing`；可显式选 `fixed_zero_anatomical_local_rotation` 作零位先验对照 |

已有官方 **v1 profile 继续使用原来的全缺测零位策略，不因升级自动启用联动**；原有配置、模型、session/epoch 绑定仍需满足。新窗口和新 profile 不会热替换正在运行的会话。

`segment_observed_mask` 仅表示该骨段有当前有效输入；`joint_observed_mask` 还要求父骨段有效；`inferred_mask` 和 `source_labels` 明示缺测先验或推断父链。联动 DIP 标为 `pip_coupled_dip_prior_not_observation`，`sparse_prior` 保存所用比例、依赖、截断及回退原因。默认布局中拇指 MCP 虽有传感器，仍受缺测 CMC 分解假设影响。**比例联动是经验先验，不是人体末节测量或上游官方 12 路算法**；它可使末节随中节弯曲，但不能保证个体对捏准确，也不能据此声称弯曲侧偏已解决。

`poses.jsonl` 保存 `mano_pose_rotvec`（16×3 MANO 轴角，弧度）、`shape_params`、`upstream_fsglove_solver_executed=true` 和源提交；未启用功能适配时为官方输出，实际适配时同时保存上述 `upstream_raw_*` 对照字段。`quality=not_accuracy_validated` 不表示人体精度通过。profile 保存实际官方内部标定数组及摘要，避免恢复时随机形状初始化改变参考矩阵；同时绑定配置、模型、会话和每节点 epoch。手掌失效隐藏全手，手指节点失效只将对应输入降为显式先验。原始记录、事件、新鲜度和有界最新帧传输仍沿用独立采集框架。

六轴 VQF 没有绝对航向观测，独立滤波器的输出不能直接当作已拥有同一公共 heading。官方三姿势提供初始参考关系，但原样执行官方函数不等于证明长期共同航向成立。功能层关闭时没有上述统一铰链相对航向估计；启用时也仅在受管理 PIP/IP 上有条件成立，不校正全手绝对 yaw。不能跨新连接或滤波 epoch 沿用旧标定，也不以任意共同朝向假设补成测量真值。

## 个性化手形 / 触指标定：实时 GUI 与 `upstream-shape`

官方 `upstream-live` 窗口提供“个性化手形 / 触指标定”面板，CLI `upstream-shape` 仍可用于离线文件。两者执行官方 `get_optimized_shape_params`：通过 manotorch 的可微 MANO 与触指损失优化 10 维 beta。**只优化手形，不是姿态、安装误差、形状的联合优化**。默认未运行时 beta 为零且 `shape_calibrated=false`；仅传入任意 beta 也不能声称已标定。

实时窗口操作：

1. 手动连接，完成三姿态安装标定；建议先做全手弯伸和必要的单指补采。点击“个性化手形”页签或首页的“个性化手形（可选）”按钮，进入同窗触指标定。首页进度显示基础标定与弯伸校准；输入尺度待核对时提示进入“诊断”，不会因其余步骤完成而显示为全部通过。
2. 在四个指对按钮中选“拇指—食指 / 中指 / 无名指 / 小指”。先让真实指尖轻触，再用另一只手操作鼠标，显式勾选对应的接触确认并点击采集。每对 **3 秒准备 → 2 秒保持**，显示剩余秒数及有效帧数。每组完成后自动保存任务检查点，逐组显示“已保存 / 待保存”，不必等四组或优化结束才保存。换指对、开始采集、取消或更换会话后需重新确认；不能触到时不要勾选，不要用力到疼痛。
3. 四对都采到有效确认帧后，点击“优化手形候选”。计算期间可取消，原先已采用手形不变；失败反馈显示在面板。采集保持实时模型显示，不用人工示意触指替代实际接触，IMU 也不会自动判断是否接触。
4. 候选就绪后可选择“预览候选”或“对比基准”。**预览只改变显示，不改变解算、姿态记录或 ROS 的已采用手形**。界面标明显示来源，逐对列出优化前后模型间隙（mm）；这是用于拟合的同批接触，不是独立精度验收。只有点击“采用候选手形”才提交。此前有可回退版本时，可点击“回退到上一次已采用手形”。
5. “导出手形文件”将候选（优先）或已采用结果保存到新 JSON；已有文件拒绝覆盖。“加载手形文件”显式验证并采用文件，未连接时也可选择为下一会话的首选手形，不会自动连接或恢复安装标定。新连接仍需三姿态采集。
6. “保存触指任务”将当前任务另存到新 JSON；存储失败时仍保留内存里的有效组，可点击“重试保存标定”或“另选保存目录”，也可另存触指任务到新位置。断开状态下可用“恢复触指任务”恢复已保存的优化任务；四组齐全即可离线优化、导出候选手形，再显式加载该手形供新会话使用。恢复的是冻结的记录姿态，**不恢复旧安装标定、功能轴或 VQF 状态，也不自动连接或续采**。部分任务可检查、另存，但不能与新连接下不同参考系的采集混合补齐；重新佩戴或连接仍需当前会话标定。

文件导入、导出、任务恢复和手形回退位于“任务与文件”；完整路径、模型间隙和能力说明位于“结果详情”。保存错误与重试操作不会随这些区域一起折叠。

接触采集、优化和应用均只由点击发起，不会自动连接、重采、优化或采用；正在进行其他标定时相互禁用。“取消触指采集 / 优化”停止当前手形操作，“重新开始标定…”仍用于中断当前标定并从安装流程重来。手形优化不修正航向漂移，不能保证真实触指、个体尺寸或人体姿态精度；缺测 DIP / CMC 先验仍会影响结果。

每次优化新建独立的 `shape_<编号>/`：`contacts.json` 保存真实采集的姿态、人工确认类别和源样本身份；`shape.json` 是可加载/另存的手形文件；`report.json` 保存逐指对拟合前后的模型间隙。触指任务检查点在优化之前独立保存，优化取消或失败不丢弃已采集组，也不产生可采用候选。应用/回退会另存新的 `profile.vNNN.json`，保留原安装与功能轴参数；触指任务、手形文件和完整会话 profile 用途不同，请不要混选。载入文件校验官方源版本与 MANO 模型摘要；旧版 CLI 文件若没有模型摘要，需用当前版本重新生成。

默认任务文件在 `<本次会话目录>/calibration/touch_<任务编号>.<版本编号>.json`；
每个版本包含当时所有已完成组，旧文件不覆盖。面板“触指任务”显示最近成功保存的完整路径；
重开程序后选择该文件恢复。若另选保存目录或另存任务，后续任务版本及优化输出使用所选位置。
三姿态采集证据也逐步保存为 `calibration/capture.<步骤>.<编号>.json`，用于留存证据，不能直接当作新连接的安装标定加载。

三姿态的原始检查缓存已改为从第一步开始保留，不再被固定 90 秒窗口截掉。缓存仍有容量上限，超限会明确要求重采，不会用缺少第一步的数据宣称输入尺度通过。新版不会热替换已经打开的窗口；正常结束旧会话后重新启动才会看到新增面板。

离线 CLI 操作时，先从同次有效官方姿态记录中选取操作者明确观察到真实接触的帧，人工整理为 JSON 文件。不会仅凭 IMU 推断是否真的接触，也不能把示意动作当作标签：

| 字段 | 文件要求 |
|---|---|
| `mano_pose_rotvec` | 有限数值数组 `[N,16,3]`；使用官方输出的 MANO 轴角，单位弧度，不是 `anatomical_euler_rad`，也不是 quaternion |
| `finger_category` | 长度 `N`；`2`=拇指触食指、`3`=触中指、`4`=触无名指、`5`=触小指；四类都必须出现 |
| `contact_labels_confirmed` | 只有操作者确已确认这些真实接触标签时设为 JSON 布尔值 `true` |

每一帧的姿态与类别按相同下标配对；可以每类多帧。当前缺测 DIP/CMC 的先验仍可能使触指姿态有偏差，优化 loss 降低不自动证明接触位置或个体手形准确。

```bash
vt-fsglove12 upstream-shape \
  --fsglove-source /你的官方FSGlove源码目录 \
  --mano-assets /你的模型目录 \
  --contacts /绝对路径/已人工确认的接触帧.json \
  --iterations 500 --seed 0 \
  --output /已存在的输出目录/official_shape.json

vt-fsglove12 upstream-live \
  --fsglove-source /你的官方FSGlove源码目录 \
  --mano-assets /你的模型目录 \
  --shape-profile /上述输出路径/official_shape.json \
  --output-root tools/fsglove12/output/upstream_live_with_shape
```

形状结果文件必须新建，已有输出拒绝覆盖。结果包含 `algorithm=upstream_fsglove_touch_shape`、beta、官方来源、接触文件摘要、迭代次数和种子；`physical_accuracy_verified=false`。`--shape-profile` 加载时记录 `upstream_shape_params`、显式 `upstream_shape_calibrated` 和 `upstream_shape_provenance`，随后保存进本次 profile，并供 MANO 渲染使用。该标识表示执行/加载了声明的优化流程，不代表通过人体测量验收。加载形状也不能省略新会话的三姿势安装标定。

## 0. 实时使用：手动连接与三步引导

### 安装与启动

实时窗口需要可信的 MANO 右手模型及相应依赖。首次安装请先完成[独立环境](#1-安装独立环境)和[MANO 环境](#4-可选-mano-环境与可信模型)，然后在**仓库根目录、同一个独立环境**中补装实时依赖：

```bash
python -m pip install -e 'tools/fsglove12[live]'
vt-fsglove12 live \
  --mano-assets /你的模型目录 \
  --output-root tools/fsglove12/output/live
```

`live` 额外安装 PyQt5、pyqtgraph、PyOpenGL、pyserial；它们不会替你取得 MANO 模型或完成模型授权。请在有图形桌面的终端运行；旧离线 `view` 使用 Polyscope，新实时窗口使用 Qt/OpenGL，两者是不同入口。

本机已验证的实时界面依赖版本见 [requirements-live-tested.txt](requirements-live-tested.txt)。以下启动不会自动停止旧窗口。

### 连接前检查

1. 确认是当前右手布局，特别是 **12 号确实位于手掌/手背、5/6 号的拇指骨段安装位置**；目前这些安装关系仍需实物核对。不要为启动界面就把“安装已确认”改成真。
2. 若旧手套窗口、IMU 波形窗口或其他程序正在占用该串口，先由操作者在旧界面点击断开或正常关闭，再连接新窗口。新工具不会自动杀进程、关闭旧 GUI 或抢占端口；本开发轮也不会替操作者完成这些动作。
3. 点击“刷新串口”，选中或输入正确端口，再点击“连接”。启动成功但未连接时，看到的是动作示意，不是手套姿态。
4. 检查 12 个通道状态、新鲜通道数量和累计样本是否更新。12/12 新鲜只表示数据到达，**不表示映射、标定或姿态精度已通过**；11 号在默认布局中只是辅助通道，不是缺测骨段的替代值。

### 三步标定：每步准备 3 秒，再保持 2 秒

三步都要求**五指自然伸直、指形保持不变，转动的是整只手掌**。不需要精准摆到 90°；倾斜约 30–60°即可，程序使用手掌 IMU 的实际转动估计方向和幅度，而不是把动作标签当作精密角度真值。

每一步先点击对应“采集”按钮：**“准备动作，暂未采集”的 3 秒内摆到目标姿势；看到“正在采集，请保持不动”后，维持该姿势 2 秒。不要等整个倒计时结束才开始动作。**

| 顺序 / 按钮 | 准备期间怎么做 | 正在采集的 2 秒 |
|---|---|---|
| 1. 平掌静止 | 右手掌心朝下，手掌大致水平，五指自然伸直 | 保持水平和指形不变 |
| 2. 指尖下倾 | 保持五指伸直，通过手腕让整个手掌的指尖向下倾约 30–60°；不是只把手向下平移 | 停在下倾姿势，保持不动 |
| 3. 拇指侧上抬 | **先回到第一步平掌**，再转动整只手掌，使拇指侧向上、小指侧向下约 30–60°；不是只抬拇指 | 停在侧倾姿势，保持不动 |

不要握拳、单独弯手指或把两次转动都做成同一方向。第三步完成、三个步骤都有数据后会自动拟合；成功后才进入已标定的实时重建。拟合失败会显示原因和建议重采步骤，已采集的其他步骤保留，不要求每次从头做。

完成的按钮会显示“✓ 重采”，可单独重采某一步；三步齐全后再次自动拟合并保存新版本。重采期间不沿用旧结果假装仍有有效标定。“取消本步采集”取消正在准备/采集的步骤并保留已完成步骤；“清除本次标定 / 重新开始”用于明确重新开始。不导入旧手套程序的 profile，也不自动套用旧失败数据。

### 拇指、小指回位偏差 / 弯曲方向 / 软件限位

2026-10-01 起，三步标定明确把第一步的中立均值映射到模型中立姿态，而不再让三姿势最小二乘的折中误差变成初始手指弯曲。安装旋转仍由原来的两方向运动估计；锚定前后拟合误差都保存。**中立误差为零是人为设定参考的结果，不是人体精度通过。** 此变化不能单独修好运动轴错误、陀螺量程不一致或后续漂移。

完成三步后，推荐按以下顺序检查：

1. 自然伸直，检查模型是否伸直。如存在明显恒定偏移，点击 **“仅重设伸直参考（保留安装轴）”**：准备 3 秒，再静止 2 秒。手掌不必回到原朝向。程序只更新新鲜手指的参考，不重启 VQF、不重置手掌朝向；失败节点保留原参考并说明原因。不要在握拳时点击：仅凭这些 IMU 不能证明你真的伸直了。
2. 点击 **“拇指弯曲方向校准”**：先自然张手，3 秒准备后保持 2 秒；看到 **“现在弯伸”** 再动。接下来 8 秒内，手掌尽量不动，将拇指从伸直弯到舒适位置，再伸直，慢慢重复 2–3 次。不必强行达到极限。窗口会切换到对应的弯曲动作示意。
3. 点击 **“小指弯曲方向校准”**，同样先张手保持，再按提示单独弯伸小指。其他手指可自然随动，不要求强行固定；模型只更新所选手指。
4. 回到实时重建后，分别缓慢弯伸、快速弯伸并停手，观察是否即时回位。画面下方显示拇指、小指弯曲角；触及软件上下限会标注并显示橙色提示。**贴限不是测得人体极限**，不能仅据此加大角度上限。

功能轴操作从父子骨段的相对旋转学习弯曲主轴与正方向，再把该轴映射到模型弯曲轴；共轭旋转保持相对旋转角幅度，没有时间平滑或把小动作放大成握拳的增益。每个关节独立处理：动作太小、样本缺失或轴方向不一致时，不覆盖该关节已有可用结果，不清除其他手指。反馈明确报告未更新关节。

这是**功能运动到模型的重定向**，不是重新测出解剖安装坐标；特别是两 IMU 拇指的根部/近节分解仍有假设，拇指根部没有因此变成实测。启用后 `residual_deg_by_slot` 是重定向后的模型拟合残差，不能当作原传感器朝向误差或人体角度误差。重新采三步或重设伸直参考后，旧功能轴不再沿用，需按需重采；断开/滤波 epoch 变化也不能跨会话复用。

成功操作保存新的 `profile.vNNN.json`，旧版本和原始数据不覆盖。`functional_fingers` 保存所选关节的参考、功能轴、依赖节点/epoch 及观测运动范围；其中的范围只是本次动作幅度，**不是自动测得的个人生理极限**。`poses.jsonl` 还包含：

- `preconstraint_relative_angles`：进入限位初始化前的局部 Euler 分解，不是另一次无约束优化结果；缺父骨段时注明推断父链。
- `active_joint_limits`：命中的关节、轴、上下界、值与来源；不把推断的末节当作独立限位观测。
- `functional_axis_retargeting`：实际应用/跳过的功能轴、传播到的子骨段及残差所在坐标域。

### 个人活动范围配置（不是自动 ROM 标定）

可复制 [right_current.json](src/vt_fsglove12/configs/right_current.json) 为个人配置，再在完整 JSON 中增加以下可选字段，启动时通过 `--config` 指定。下面**仅展示默认数值的等价写法**，不是对你的手测得的推荐范围：

```json
{
  "joint_limits_rad": {
    "7":  {"y": [-0.65, 0.65], "z": [-0.25, 1.65]},
    "8":  {"z": [-0.15, 2.2]},
    "14": {"y": [-0.65, 0.65], "z": [-0.25, 1.65]},
    "15": {"z": [-0.15, 1.7]}
  },
  "dip_ratio_by_finger": {"little": 0.65}
}
```

这是配置片段，不能代替包含映射、采样率和单位等字段的完整配置。单位为 **rad**（角度乘以 π/180），`z` 为模型弯曲分量，`y` 为外展分量。这里的 7/8/14/15 是 **MANO 骨段槽位，不是 IMU 编号**：分别对应小指近节/中节、拇指近节/远节。省略字段继承原默认值。逐指耦合键支持 `index/middle/ring/little`，只在末节未观测时应用；小指末节仍是推断，不应伪称独立测量。

应先确认伸直参考、功能方向和输入尺度，再根据可验证的活动范围修改限位；当前没有自动学习人体极限，也没有默认放宽全手约束。修改配置后需新建连接并重新标定，不能把新约束配置套到摘要不匹配的旧 profile。

### 如何判断界面显示的是什么

| 提示颜色 / 文案 | 含义 |
|---|---|
| 橙色“动作示意” | 人工指定的 MANO 姿势，用于指导动作，**不是你的实时手势**；未标定和采集过程中都可能显示 |
| 绿色“实时重建” | 当前数据经本次标定与求解得到的实验结果，仍有缺测推断；不是准确度认证 |
| 绿色“回放重建” | 来自旧 CSV 的重建，不是现场设备 |
| 橙色“姿态触及软件限位” | 当前有求解变量贴限，可能出现动作死区；不是人体极限测量 |
| 红色“无新鲜可用姿态” | 当前没有可展示的有效结果，隐藏手模型，不保持旧姿态冒充实时 |

断开会清除本次标定，因此之后可能回到橙色的未标定动作示意，而不是一直显示红色。遇到渲染错误也会隐藏模型并显示原因。手掌数据缺失会影响完整手姿；局部缺测会在反馈/推断标记中说明，不能把补出的末节当传感器实测。

界面“重建画面更新 Hz”是画面更新次数，不是 IMU 实际采样率或端到端延迟测量。视觉流畅与人体姿态准确是两回事。

### 实时性能与卡顿排查

实时入口默认使用独立计算进程；启动方式和三步标定操作不变：

```text
计算进程：串口读取 / VQF → 姿态求解 → MANO 网格（串行计算）
                                  ↓ 有界最新值快照，不排队播放旧帧
界面进程：读取最新快照 → 更新顶点与关节 → Qt/OpenGL 绘制
```

数值求解和 MANO 不在界面刷新回调中执行，也不在同一进程中分别用相互争用的求解/网格线程执行。只有新帧或连接、标定、错误等状态变化时才复制并传输快照，不反复发送同一网格。网格拓扑、邻接和掌背颜色只建立一次，后续只更新顶点与向量化法线。三张标定动作示意在开始采集前预先计算。进程隔离不改变标定、六轴融合、关节约束、缺测推断或求解容差；没有增加平滑滤波来换取视觉稳定。

界面会显示求解耗时、网格计算耗时、界面更新耗时和“提交网格时姿态年龄”。后者是姿态时间戳到交给绘图控件的时间，**不包含传感器内部延迟、实际屏幕呈现延迟，也不是端到端延迟认证**。界面更新次数不等同于显示器呈现帧率。求解、传输或界面暂停使结果过期时会隐藏旧模型，不会把旧帧标成实时。

若仍卡顿，先区分“求解/网格耗时大”与“界面更新耗时大”，不要因此重做成功标定或调大平滑系数。计算进程失效会显示错误并隐藏旧姿态，不会自动重连设备。正常关闭窗口会请求计算进程结束、关闭串口并完成记录；未结束时会保留窗口提示，不强制杀掉持有串口的进程。

更新代码不会热替换已经运行的旧窗口。为保护正在进行的成功实验，开发或升级不会自动关闭旧程序；需要切换版本时，先正常结束旧会话，再按上述入口启动。**重新连接仍会重建 VQF，需按原有会话规则标定；不能因仅更新显示代码就跨会话复用旧航向。** 自定义 Python 启动脚本须将创建窗口/启动计算进程的代码放在 `if __name__ == "__main__":` 保护中；标准命令行入口已处理。

开发者可用[性能回放脚本](scripts/benchmark_live_ui.py)测量真实 MANO、进程传输和桌面 OpenGL 链路，不打开串口、不操作已有窗口：

```bash
env OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  python tools/fsglove12/scripts/benchmark_live_ui.py \
  --session /已有会话目录 --mano-assets /你的模型目录 \
  --duration 8 --output /新建结果路径/performance.json
```

脚本需在已安装本工具的独立环境和图形桌面中执行，自动打开并关闭它自己的回放窗口。只使用该会话的 `orientations.jsonl` 与匹配的 `profile.v001.json`，不修改源数据。默认取最新 120 帧；如录制后段发生过滤波器重置，须用 `--start-frame N --frames 20` 指定已确认与该标定匹配的连续区间，不会篡改 epoch 强行通过。区间会循环并重置播放时钟，结果只用于性能比较，不包含串口接收、VQF、原始记录开销或人体精度验证。输出已有文件会拒绝覆盖。

2026-09-30 本机短时验证：同一批真实录制 20 帧的独立求解中位耗时从 **39.06 ms 降至 23.14 ms**，最大关节角差约 `1.69e-8 rad`。用这 20 帧循环进行 8 秒真实桌面 OpenGL 回放，有效新网格提交为 **25.34 Hz**，界面更新 P95 **5.17 ms**，未复现此前秒级阻塞。计算进程总耗时 P95 仍为 **38.15 ms**，**尚未稳定达到 30 Hz**；独立求解基准不能代替整条链路的结果，也不能代替长时间真机验收。

### 会话保存、断开与恢复

点击连接后会创建唯一新会话目录并开始记录，不需另找录制按钮；启动未连接的窗口不会自动采集。主要文件如下：

```text
tools/fsglove12/output/live/<UTC时间_会话ID>/
├── config.json            本次配置快照
├── rest.json              本次 MANO 参考帧
├── session_metadata.json  输入来源；区分 raw_serial 与 csv_replay
├── raw.csv                原始整数、主机时间及原始 status；不改写原始输入
├── orientations.jsonl     独立 VQF 朝向、节点新鲜度、sample_index / epoch
├── poses.jsonl            求解姿态或明确的不可用状态、标定版本
├── events.jsonl           连接、采集、拟合、错误等事件
├── profile.json           首次成功拟合的副本；不是“自动更新的最新版”
├── profile.v001.json      成功标定版本；重采成功后新增 v002、v003……
└── summary.json           正常断开/结束时汇总计数、版本、结束原因及记录错误
```

标定失败时不会产生成功 profile；异常关闭或写入失败可能只留下部分文件。请看 `summary.json` 的结束原因、`recording_complete` 和错误信息；文件存在不等于录制完整，更不等于标定准确。运行中的会话通常尚无最终 summary，不要据此判断丢失。

点击“断开”或正常关闭窗口以结束记录。断线不会自动重连；重新手动连接会创建新会话、重建滤波并**清除标定，需重新做三步**，不能跨独立初始航向沿用旧 profile。数据长间断导致节点 epoch 改变时，也不能继续把该节点旧标定视为有效。

### 串口已连接，但没有 IMU 数据

“连接成功”仅表示串口已打开，不代表已经收到正确的 IMU 数据。界面的串口接收计数和状态提示区分：

| 当前证据 | 提示与下一步 |
|---|---|
| 尚未收到任何字节 | 检查 IMU 采集板供电、USB 连接与端口，不开始标定 |
| 收到少量字节，尚未组成完整帧 | 等待后续数据；不把拆包自动判为错误 |
| 收到字节且持续解析丢弃、没有解码 IMU 帧 | 核对选中的是 IMU 板而非触觉板，以及协议是否匹配；这不是对所接硬件类型的自动识别 |
| 已解码 IMU 帧，但手掌或部分节点过期 | 按缺失节点排查；历史有效帧计数不表示当前仍有新鲜数据 |

这些被动计数来自已有的唯一串口读取者，不额外读取、不发送查询命令、不改变原始值或标定条件。`runtime.input_diagnostics`、`orientations.jsonl` 的 `input_diagnostics` 和正常关闭后的 `summary.json` 保存字节数、帧数、解析丢弃字节数、剩余缓冲及最近字节/样本年龄。年龄以其中 `observed_monotonic_s` 为观察时刻，不能把慢处理期间的旧快照当作刚刚测得。累计接收与帧数不是硬件采样率，也不证明 CRC 或未知状态字节校验通过。旧会话和文件回放没有此字段时不编造计数。

长时测试期间请避免合盖或系统自动休眠。若系统休眠/恢复导致长断流并重置滤波器，应按下节提示重新标定；程序不会将恢复后的旧标定伪装为仍有效，也不会自行更改系统电源设置。

### 原始 12 路 IMU 字节采集与 16 位边界分析

需确认编码边界值是否已经存在于 STM32 输出时，使用独立串口探针，先保存串口返回的原始字节，再离线分析；不经过输入滤波、VQF 或姿态求解。
标定窗口、`Ploy_IMU.py` 等必须先断开该 IMU 串口；窗口可以保留，但采集期间不要点击连接。
独立触觉串口无需停止。探针不发送固件命令、不清空接收缓冲、不自动重连，独占采集最多 30 秒后释放串口。
打开/关闭串口本身仍可能影响设备，首次读取可能包含打开前已缓存的数据。

在工程根目录执行，替换明确核实的 IMU 串口和全新的输出文件名；不要误选触觉板：

```bash
mkdir -p "$HOME/visiontactile-data/imu_raw_packets"
.venv-fsglove-120hz/bin/python tools/fsglove12/scripts/probe_imu_wire.py \
  --connect --port '/dev/serial/by-id/<你的IMU串口>' \
  --duration-s 30 --max-bytes 4194304 --max-samples 100000 \
  --report "$HOME/visiontactile-data/imu_raw_packets/probe01.json"

.venv-fsglove-120hz/bin/python tools/fsglove12/scripts/analyze_imu_wire.py \
  --wire "$HOME/visiontactile-data/imu_raw_packets/probe01.json.wire.bin" \
  --probe-report "$HOME/visiontactile-data/imu_raw_packets/probe01.json" \
  --output-dir "$HOME/visiontactile-data/imu_raw_packets/probe01_analysis"
```

探针生成原始 `.wire.bin` 与包含 SHA256、接收量和时长的 JSON；分析器拒绝摘要不匹配及覆盖已有输出目录。
分析目录中的 `samples.csv` 保留每条六轴原始整数、无符号解释和字节位置，`summary.csv` 列出 12 路 × 6 轴的最小/最大值及边界计数；
`boundary_events.csv` 保存 `abs(value) >= 32760` 的具体事件，`wrap_candidates.csv` 单独列出疑似跨正负边界的跳变，`report.json` 汇总结果。
二进制不包含逐条设备时间戳，分析器只使用帧序号、节点内序号和字节偏移定位，不伪造采样时间。

当前协议按每节点 `ID + status + GX/GY/GZ/AX/AY/AZ`（`<BB6h`）解释，六轴范围必然为 **−32768～32767**。
“超范围计数为零”不能排除 STM32 在封装前发生溢出/截断；无符号解释大于 32767 通常对应负数，不能算作溢出。
接近边界、命中端点或疑似回绕也不能单独证明物理饱和。当前帧同步仅核对六个节点 ID，没有已验证的 CRC，必须保留原始字节证据。

如果标定窗口已经连接且希望保留当前标定，不要同时开启串口探针；可以只读分析当前会话的 `raw.csv`：

```bash
.venv-fsglove-120hz/bin/python tools/fsglove12/scripts/analyze_imu_csv.py \
  --raw-csv '/本次会话目录/raw.csv' --last-seconds 30 \
  --output-dir '/全新的输出目录'
```

该文件在输入滤波与 VQF 前写入原始整数。分析器只读取打开文件时已有的前缀（上限 64 MiB），
忽略尚未写完的末行，按最后完整样本的主机时间截取所选窗口；`samples.csv` 逐字节保留选中行，
`summary.csv`、`boundary_events.csv`、`report.json` 分别保存逐轴统计、具体边界事件与来源摘要。
CSV 中超出 `−32768～32767` 的整数会直接计数，不强转为 int16、不截断或过滤。
这条路径不会打开或断开串口，但证据是**解析后的未滤波整数**，不是独立采集的串口二进制，不能重建并冒充原始字节。

### 短暂卡顿后没有姿态：先区分过期与滤波重置

从 2026-10-01 的接收间隔修复版起，**显示新鲜度与滤波器重置使用独立阈值**，实时采集和离线原始数据回放采用相同策略：

| 配置 / 事件 | 默认值及行为 |
|---|---|
| `stale_after_s` | **0.15 秒**。超过该年龄的节点不进入当前姿态；手掌过期时隐藏旧模型，不延长显示时间掩盖卡顿 |
| `filter_reset_gap_s` | **1.0 秒**。某节点下一条原始数据的主机时间与上一条间隔超过此值，才重建该节点 VQF 并递增 epoch |
| 150 毫秒以上、1 秒以内的接收间隔 | 保留滤波状态与 epoch，记录短间隔警告；新鲜数据恢复后可沿用同会话标定，不必仅因这次间隔重新做三步 |
| 主机单调时间倒退 | 仍清空滤波状态、递增 epoch，拒绝继续使用原 epoch 标定 |
| 真正断开后重新连接 | 仍是新会话；本修复不实现跨会话标定恢复 |

两项均为秒。重置阈值必须有限且不小于新鲜度阈值；未提供重置阈值的配置补入 `max(1.0, stale_after_s)`，新会话 `config.json` 保存实际生效的值。要**仅为历史算法对照**复算旧行为，可以显式将两项设为相同值；默认不再如此。

例如本次观察到约 **164 毫秒** 的主机接收间隔：旧程序会重建全部 12 路滤波器，使旧标定失效；新策略仅记录短间隔并保留滤波器。**主机读取/解析间隔不是传感器硬件采样间隔**，仅凭它不能分辨 USB 缓冲、计算调度停顿或真实丢样。因此程序不会补造样本，也不会把 164 毫秒当成单条样本的积分周期；每条收到的原始样本仍按配置的名义采样周期处理。保留状态不等于已经证明无丢样、无漂移或人体姿态准确。

界面现在区分“手掌数据暂时过期”“滤波状态已重置、标定失效”和“本次连接尚未标定”。遇到短暂过期，先保持连接等待新数据，不要反复点归零或断开。确认滤波器已重置时，仅重设伸直参考不能恢复失效的安装/航向标定；需在当前稳定会话重新做三步。

`orientations.jsonl` 中的 `gap_diagnostics` 保留每节点短间隔次数、长间隔重置次数、最后间隔长度、时间和动作；`node_N_short_gap_filter_preserved` 为短间隔警告。次数按节点统计，一次全链路停顿可能计为 12 个节点事件。离线报告新增 `short_gaps`；原 `gaps` 仍指因长间隔实际重置的次数。旧录制、旧 profile 及其 epoch 不会被改写；修改间隔策略后不能把新的重算结果冒充与旧 profile 原样匹配。

更新文件不会热替换已运行进程。要让新策略生效，需要正常结束旧窗口并重新启动；这次重启仍需当前会话标定一次。已经重建过的旧 VQF 状态不能靠修改阈值追溯恢复。

本次回归使用故障会话中同一窗口的 **10,080 条真实原始样本**（每路 840 条），最大单节点接收间隔 **163.975 ms**：旧策略 12 路全部重置，新策略 12 路均不重置，两者处理样本数相同；在间隔内超过 150 ms 的检查点，两者都隐藏过期节点。可用[离线回归脚本](scripts/verify_gap_recovery.py)重跑该故障窗口，不打开串口，不加载历史标定：

```bash
python tools/fsglove12/scripts/verify_gap_recovery.py \
  --raw /故障会话目录/raw.csv \
  --start 269683 --end 269690 \
  --output /尚不存在的目录/gap_regression
```

该脚本针对这次 **12 路短间隔事件**，最多读取文件末尾 150,000 条记录；时间范围是上述故障会话的主机单调时间，不适用于任意新会话。输出包含选定原始窗口及 JSON 对照报告。滤波器从窗口起点重新初始化，标定兼容检查仅使用离线自建的身份变换测试 profile，不证明历史标定可恢复或真实角度准确。另用真实 VQF 验证 164 ms 后保留 epoch、1.036 秒后重置并拒绝旧 epoch。接收间隔修复后的完整测试集（真实 MANO 与 Qt）为 **361 passed**。

## 5. 离线标定接口：显式标签，不自动推断用户做了哪个动作

```bash
  --output tools/fsglove12/output/session01/profile.json
```

每个传感器求解 `Y × R_sensor × X = R_label`：`X` 为传感器与骨段安装旋转，`Y` 为本次滤波初始坐标对齐。缺少某手指标定只报告该节点；没有手掌标定则不能产生全手结果。

标定绑定**同一份四元数文件、配置、模型参考帧及每节点 epoch**。不能跨重启沿用独立滤波器的初始航向。初始对齐后仍可能出现相对航向漂移，本版本不宣称已完成在线校正。

## 6. 求解与真实网格回放

```bash
vt-fsglove12 solve \
  --orientations tools/fsglove12/output/session01/orientations.jsonl \
  --profile tools/fsglove12/output/session01/profile.json \
  --rest tools/fsglove12/output/session01/rest.json \
  --output tools/fsglove12/output/session01/poses.jsonl \
  --report tools/fsglove12/output/session01/solve_report.json
```

求解采用每帧受限姿态拟合，不使用旧解算器，不用“静止自动伸直”，也没有为了稳定画面而加重时间平滑。模型关节限位和缺测先验仍是实验设置，并非完成每个人的解剖标定。

主要输出：

- `anatomical_euler_rad`：16×3、内旋 XYZ、单位弧度；根旋转另存于 `root_quat_xyzw`。
- `segment_observed_mask`：骨段当前存在有效输入；不等于关节角直接测量。
- `joint_observed_mask`：该关节的父、子骨段都有输入；仍是受限拟合，不是绝对真值。
- `inferred_mask/source_labels`：缺测比例推断、拇指先验、缺失父段分解等。
- `residual_deg_by_slot`：模型对输入方向的拟合误差，不是实物准确度。
- `quality`：实验、部分可用、不收敛或不可用。手掌缺失时不给完整姿态；局部缺测不停止其余手指。

显示真实网格需要 Polyscope，并在 Linux 图形会话中执行。第 4 节的可选清单已包含所测安装版本；仅需补装查看器时：

```bash
python -m pip install 'polyscope==2.6.1'
vt-fsglove12 view \
  --poses tools/fsglove12/output/session01/poses.jsonl \
  --mano-assets /你的模型目录
```

查看器消费已求解的离线文件，有播放/暂停和帧定位，不伪装成实时串口。模型与求解参考帧不匹配会明确报错，不暗中换模型。没有 MANO 时，不用另一只“看起来像手”的模型冒充 FSGlove 运行成功。当前模型数学测试和 EGL 截图检查通过，不代表离线播放器的桌面交互已完成验收。
